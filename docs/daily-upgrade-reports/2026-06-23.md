# AI팀 일일 업그레이드 보고 — 2026-06-23

## 🔍 벤치마킹 인사이트

1. **알람 피로(Alarm Fatigue) 문제**: 예지보전 프로젝트의 70%가 실질적 인사이트 없이 경보만 생성하여 실패한다. "AI 사용"과 "AI에서 가치 창출" 간의 격차는 올바른 도구를 올바른 문제에 적용하는 것에 달려 있다. (출처: AI Agent Brief 2026)

2. **Edge AI + 5G 수렴**: Gartner 2025 전략 기술 트렌드에 따르면 엣지 컴퓨팅은 실시간 이상 감지를 위한 필수 요건이 됐다. IIoT 센서의 진동·열·음향·공정 텔레메트리를 AI 모델과 결합하면 고정 임계값 모니터링보다 30~50% 더 일찍 결함을 감지할 수 있다.

3. **자동차 부품 예지보전 시장 급성장**: 2030년까지 $167.5억 규모로 성장 전망. 이미 전 세계 제조업체의 47%가 예지보전 기술을 도입했으며, AI 예지보전 적용 시 비계획 다운타임 30% 감소, OEE 15~45% 향상, 6주 내 ROI 달성이 보고되고 있다.

4. **에이전트형 AI(Agentic AI) 전환**: 2026년은 파일럿에서 실제 생산 규모 배포로 전환되는 해다. 멀티에이전트 시스템이 생산 용량·인력·자재 가용성 제약을 실시간으로 조율하며, MCP(Model Context Protocol)로 에이전트가 라이브 데이터에 접근하는 아키텍처가 표준화되고 있다.

5. **자연어 기반 공장 관리**: Siemens Industrial Copilot, Rockwell Automation AI 등 주요 솔루션이 자연어로 PLC 코드 생성·디버그, 설비 오류 코드 해석, 작업 지시 자동화를 구현하고 있다. QAD Redzone처럼 "수동 인사이트에서 자율 실행"으로 이동하는 플랫폼이 2026 Hannover Messe에서 핵심으로 부각됐다.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 본사(한국) ↔ 인도 현장 간 기술 용어 표준 용어집(Glossary) DB를 Supabase 테이블로 구축하여, 번역 전 자동 조회·일관성 보장
  - 설비 오류 코드, 품질 리포트 등 반복 포맷 문서는 번역 템플릿 프롬프트화하여 처리 속도 향상
  - 에이전트형 AI 트렌드에 맞게 번역 결과물을 구조화 JSON으로 출력해 다른 팀원(data-analyst, planner)이 바로 소비할 수 있도록 파이프라인화
- **적용 우선순위:** 🔴 High — 용어집 DB 구축 → 🟡 Medium — 템플릿 프롬프트 정비 → 🟢 Low — JSON 출력 포맷 표준화

### data-analyst
- **개선 제안:**
  - 현재 수동 Excel/CSV 분석을 자동화: Supabase Edge Function + 스케줄러로 일일 KPI 리포트(OEE, 불량률, 다운타임) 자동 생성
  - 알람 피로 방지를 위해 KPI 임계값 트리거 기반 이상 감지 로직 도입 — 단순 경보가 아닌 "원인 + 권장 조치"까지 포함하는 인사이트 카드 형태로 출력
  - 예지보전 데이터(진동·온도 센서)를 Supabase에 연동하여 트렌드 분석 대시보드에 실시간 피드 추가
- **적용 우선순위:** 🔴 High — KPI 자동 생성 스케줄러 → 🔴 High — 이상 감지 임계값 로직 → 🟡 Medium — 센서 데이터 연동

### web-builder
- **개선 제안:**
  - FMS 포털에 설비별 예지보전 현황 패널 추가: 센서 상태(정상/주의/위험) 배지 + 잔여 수명 예측값 표시
  - Next.js 14 Server Actions를 활용해 작업지시(Work Order) 생성·갱신을 페이지 리로드 없이 처리, 현장 태블릿 UX 최적화
  - PWA(Progressive Web App) 전환 검토 — 오프라인 모드에서도 최근 설비 데이터 조회 가능하도록, 인도 공장 네트워크 불안정 환경 대응
- **적용 우선순위:** 🔴 High — 예지보전 패널 UI 구현 → 🟡 Medium — Server Actions 기반 Work Order UX → 🟢 Low — PWA 전환

### planner
- **개선 제안:**
  - 멀티에이전트 협업 트렌드에 맞춰 FMS 포털 내 "AI 에이전트 역할 명세" 문서 작성: 각 팀원 에이전트의 입력·출력·트리거 조건을 플로우차트로 정의
  - 설비 DB 스키마에 `maintenance_history`, `failure_mode`, `sensor_threshold` 테이블 추가 설계 — 예지보전 기능 확장 기반 마련
  - 스프린트 계획 시 "검증 가능한 인수 조건(Acceptance Criteria)" 명시 의무화하여 evaluator 팀과의 협업 효율 향상
- **적용 우선순위:** 🔴 High — 설비 DB 스키마 확장 설계 → 🔴 High — AI 에이전트 역할 명세 → 🟡 Medium — AC 명시 프로세스 표준화

### evaluator
- **개선 제안:**
  - QA 체크리스트를 자동화된 테스트 스크립트(Playwright E2E)로 전환하여 수동 3회 반복 검증 부담 경감, 회귀 방지
  - 각 기능 검증 시 "알람 피로 방지 원칙" 적용: 실제 현장 사용자 시나리오(인도 현장 엔지니어 페르소나) 기반으로 검증 케이스 설계
  - 검증 결과를 Supabase `qa_results` 테이블에 자동 기록하여 data-analyst가 품질 트렌드 분석에 활용할 수 있도록 구조화
- **적용 우선순위:** 🔴 High — Playwright E2E 스크립트 도입 → 🟡 Medium — 현장 페르소나 기반 검증 케이스 재설계 → 🟢 Low — QA 결과 DB 연동

## 💡 오늘의 효율화 제안

1. **팀 간 데이터 파이프라인 표준화**: translator → data-analyst → web-builder로 이어지는 데이터 흐름에 공통 JSON 스키마를 정의하면 각 팀원 간 핸드오프 시 재가공 시간을 50% 이상 줄일 수 있다. Supabase Realtime을 허브로 활용해 팀 전체가 동일한 최신 데이터를 바라보는 단일 진실의 원천(Single Source of Truth) 구조를 구축할 것을 권장한다.

2. **주간 "인사이트 카드" 루틴 도입**: 매주 월요일 아침, data-analyst가 지난 주 KPI 이상 징후 Top 3를 "인사이트 카드" 형태(원인·영향·권장 조치)로 발행하고, planner가 해당 주 스프린트 우선순위에 반영하는 루틴을 확립한다. 이를 통해 현장 데이터가 실제 개발 우선순위에 반영되는 피드백 루프를 완성한다.
