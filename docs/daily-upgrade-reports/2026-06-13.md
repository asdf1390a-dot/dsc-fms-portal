### 핵심 인사이트 5가지

1. **Generative AI 유지보수 ROI 급등** — 생성형 AI가 비계획 다운타임을 25~40% 감소시키고, 과거 며칠 걸리던 SOP 자동 생성 및 현장 기술자용 수리 컨텍스트 즉시 제공이 가능해졌다. 2025~2026년 예측유지보수 시장은 30.5% CAGR로 $14.3B → $28.2B 성장 예상.

2. **멀티에이전트 아키텍처가 표준으로** — 단일 AI 모델 응답 방식에서 벗어나, 실시간 데이터 소스에 연결된 에이전트 간 조율(agent-to-agent coordination) 체계가 2026년 팩토리 AI의 기준 아키텍처로 자리잡음. 진동·온도·전류 센서 데이터를 멀티에이전트가 실시간 처리 → 고장 전 발주·점검 트리거 자동화.

3. **자동차부품 특화 AI 도구 진화** — Tractian Smart Trac Ultra 등 센서+AI 진단 통합 솔루션이 제조사 무관하게 회전기기(모터·펌프·압축기·기어박스) 고장을 고정임계값 모니터링 대비 30~50% 조기 탐지. 진동·열화상·음향·공정 텔레메트리 융합이 핵심.

4. **AI 준비도 격차(Readiness Gap)** — 제조업체 98%가 AI를 탐색 중이나, 실제 스케일 운영에 준비된 곳은 20%에 불과. 가장 빠르게 확장한 기업들의 공통점은 린(Lean) 프로세스 규율 선행 구축. AI 리터러시보다 프로세스 규율이 선행 조건.

5. **워크플로 비효율 비용** — 중소 제조사 평균 연간 $340,000 손실이 수동 생산 스케줄링 오류·공급업체 커뮤니케이션 지연·품질관리 문서화 공백에서 발생. 2026년 AI 에이전트 도입으로 이 비용을 구조적으로 제거하는 방향으로 이동 중.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 한↔영 번역 프롬프트에 자동차부품 제조 도메인 용어집(Tool, Die, Jig, BOM, PPAP, SOP 등) 을 RAG 레퍼런스로 연결하여 번역 일관성 향상
  - 본사-인도 커뮤니케이션 특성을 반영한 "격식체/비격식체 전환" 옵션 프롬프트 추가 (이메일 vs. 메신저 메시지 구분)
  - 번역 품질 자동 백체크: 번역 결과를 역번역(EN→KO)하여 원문과 의미 차이 감지 후 플래그 부착
- **적용 우선순위:** 🔴 도메인 용어집 구축 → 🟡 격식체 옵션 → 🟢 역번역 검증 루프

### data-analyst
- **개선 제안:**
  - Supabase KPI 데이터를 실시간 스트리밍으로 수집하는 대시보드 쿼리 최적화 (현재 배치 분석 → 준실시간 이상 탐지로 전환)
  - 예측유지보수 트렌드 감지: 설비별 OEE·MTBF·MTTR 시계열에 이상 탐지 모델(Z-score 또는 IQR 기반) 적용하여 경보 자동 생성
  - Excel/CSV 보고서에 "인사이트 요약 섹션" 자동 삽입 — 수치 나열이 아닌 경영진용 1-2줄 해석 포함
- **적용 우선순위:** 🔴 이상 탐지 모델 적용 → 🟡 준실시간 쿼리 최적화 → 🟢 요약 자동화

### web-builder
- **개선 제안:**
  - Next.js 14 App Router의 Server Actions + Supabase Realtime을 활용한 설비 상태 실시간 업데이트 구현 (폴링 방식 제거)
  - FMS 포털에 AI 챗 인터페이스 추가 — 현장 작업자가 자연어로 설비 이력·정비 일정 조회 가능하도록 (claude-haiku-4-5 API 연동)
  - Lighthouse 성능 점수 모니터링 자동화: CI/CD에 Lighthouse CI 추가하여 배포마다 Core Web Vitals 추적
- **적용 우선순위:** 🔴 Realtime 연동 → 🟡 AI 챗 인터페이스 → 🟢 Lighthouse CI

### planner
- **개선 제안:**
  - 멀티에이전트 아키텍처 기반 FMS 기능 로드맵 재검토 — 단순 CRUD 기능명세에서 "에이전트가 자율 실행하는 워크플로" 관점으로 기능 명세 방식 전환
  - DB 스키마에 감사 로그(audit log) 테이블 표준화 — 모든 상태 변경에 `changed_by`, `changed_at`, `prev_value`, `new_value` 컬럼 일관 적용
  - UI/UX 설계 시 모바일-퍼스트 현장 작업자 페르소나 추가 (현재 데스크톱 중심 설계 보완)
- **적용 우선순위:** 🔴 감사 로그 스키마 표준화 → 🟡 모바일-퍼스트 UX 추가 → 🟢 에이전트 기반 기능명세

### evaluator
- **개선 제안:**
  - 3회 반복 검증 루틱에 "자동화 회귀 테스트" 1단계 추가 — 신규 기능 배포 전 기존 핵심 경로(설비 등록·정비 이력 조회·KPI 계산) Playwright E2E 테스트 실행
  - 검증 체크리스트를 GitHub Issue 템플릿과 연동하여 QA 결과를 코드 리뷰와 동일 채널에서 추적
  - AI 생성 코드의 보안 취약점 점검 항목 추가: SQL Injection, IDOR, 인증 우회 3가지를 필수 검증 항목으로 표준화
- **적용 우선순위:** 🔴 Playwright E2E 회귀 테스트 → 🟡 보안 점검 항목 표준화 → 🟢 GitHub Issue 연동

## 💡 오늘의 효율화 제안

1. **에이전트 오케스트레이션 파이프라인 도입** — translator·data-analyst·evaluator가 현재 각자 독립 실행 중인 작업을 하나의 공유 컨텍스트로 연결. 예: data-analyst가 KPI 이상 탐지 → translator가 본사 보고용 이메일 초안 자동 생성 → evaluator가 내용 정확성 검증. 세 에이전트 간 핸드오프를 Supabase 작업 큐 테이블로 관리하면 수동 코디네이션 없이 연속 워크플로 구현 가능.

2. **"린 먼저, AI 나중" 원칙 적용** — 벤치마킹 결과 AI 확장 성공 기업의 공통점은 프로세스 규율 선행. 현재 FMS 포털의 각 기능 명세에 "이 프로세스가 수동으로도 명확히 문서화되어 있는가?" 검증 단계를 planner 체크리스트에 추가 권장. 자동화 전 표준화가 AI ROI의 핵심.
