# AI팀 일일 업그레이드 보고 — 2026-07-20

## 🔍 벤치마킹 인사이트

1. **에이전틱 AI 유지보수 자동화**: 2026년 제조업의 화두는 단순 알림을 넘어선 "에이전틱 AI"로, 이상 감지 → ERP 부품 재고 조회 → 담당 기술자 배정 → 수리 일정 수립 → 작업 지시서 자동 생성까지 멀티스텝 워크플로우를 자율 실행한다. 이는 FMS 포털의 다음 발전 방향과 직결된다.

2. **자동차 부품 제조사 AI 도입 효과**: 선도 자동차 부품 제조업체 기준 예상치 못한 설비 중단 45% 감소, 유지보수 비용 28% 절감, 조립 라인 가동률 99.7% 달성. Volvo는 AI 도입 후 진단 시간 70% 단축, BMW는 ML 기반 고장 패턴 히트맵으로 연간 8시간 이상의 라인 중단을 예방했다.

3. **OEE 격차 확대**: AI 예측 정비를 도입한 공장은 캘린더 기반 정기 점검만 수행하는 공장 대비 OEE(Overall Equipment Effectiveness)가 15~20% 높게 나타나며, 투자 회수 기간은 단계적 도입 시 3~6개월 수준이다.

4. **멀티에이전트 워크플로우 아키텍처 부상**: 전문 역할을 가진 복수의 AI 에이전트가 협업하는 "에이전틱 AI 워크플로우"가 표준으로 자리 잡고 있다. 각 에이전트가 추론(Reason) → 계획(Plan) → 행동(Act) → 모니터링(Monitor) → 재시도(Retry) 사이클을 반복하며 전체 생산 관리를 지원한다.

5. **단계적 도입 전략**: 한 가지 운영 영역에서 시작해 점차 확장하는 방식이 가장 빠른 ROI를 달성한다. 반복적 의사결정이 많고 운영 데이터가 풍부한 영역(예: 설비 예측 정비, KPI 이상 감지)에서 최대 효과가 발생한다.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 자동차 부품·제조업 도메인 특화 용어집(Glossary) 구축: 한↔영 기술 용어(예: 공차, 가공, 불량률, SOP 등)를 Supabase에 저장하고 번역 시 자동 참조하도록 개선
  - 본사(한국) ↔ 인도 현장 커뮤니케이션에서 반복되는 문서 유형(회의록, 품질 보고서, 불량 사유서)에 대한 프롬프트 템플릿 라이브러리 정비
  - 번역 품질 이력 관리: Supabase에 원문/번역문/검토자 기록을 남겨 품질 트렌드 추적

- **적용 우선순위:** 높음 — 도메인 용어집 불일치는 본사-현장 간 오해의 핵심 원인

### data-analyst
- **개선 제안:**
  - KPI 이상 감지 자동화: 기존 Excel/CSV/Supabase 데이터에 통계적 이상치 탐지(Z-score, IQR) 레이어 추가하여 담당자가 수동으로 찾기 전에 경보 발생
  - 설비별 성능 지표 예측 추세 분석(7일/30일 이동 평균 + 선형 회귀)를 표준 KPI 리포트에 포함
  - 자연어 요약 자동 생성: 주간 KPI 데이터를 읽어 "지난주 대비 Line 3 불량률 12% 증가, 원인: 금형 교체 주기 초과" 형태의 경영진용 한국어 인사이트를 자동 작성

- **적용 우선순위:** 높음 — 이상 감지 자동화는 즉시 적용 가능하며 다운타임 감소와 직결

### web-builder
- **개선 제안:**
  - FMS 포털에 WebSocket 기반 실시간 설비 상태 대시보드 추가: Supabase Realtime을 활용해 센서 데이터 변화를 새로고침 없이 반영
  - 공장 현장 작업자를 위한 모바일 최적화 뷰(PWA) 구현: 태블릿/스마트폰에서 작업 지시서 조회 및 완료 처리 가능하도록 UI 개선
  - 에이전틱 워크플로우 트리거 API 엔드포인트 설계: 이상 감지 시 자동으로 담당자 알림 → 작업 지시서 생성 → 부품 재고 확인 순서로 진행되는 Next.js API route 구현

- **적용 우선순위:** 중간 — 모바일 뷰는 즉시 착수, 에이전틱 API는 planner와 스펙 확정 후 진행

### planner
- **개선 제안:**
  - 예측 정비 모듈 UI/UX 명세 작성: 설비별 RUL(잔여 수명), 이상 경보 목록, 정비 이력, 부품 재고 현황을 한 화면에서 확인할 수 있는 대시보드 설계
  - 에이전틱 워크플로우 설계: "이상 감지 → 진단 → 담당자 배정 → 작업 지시 → 완료 확인" 5단계 플로우를 상태 머신으로 명세하고 Supabase 스키마에 반영
  - 멀티에이전트 역할 분담 프레임워크 정의: translator, data-analyst, web-builder, evaluator 각각의 입출력 계약(Input/Output contract)을 문서화하여 병렬 작업 충돌 방지

- **적용 우선순위:** 높음 — 에이전틱 워크플로우 명세는 web-builder와 data-analyst 업그레이드의 선행 조건

### evaluator
- **개선 제안:**
  - KPI 계산 정확도 자동화 테스트: 알려진 입력값 세트로 data-analyst 출력을 검증하는 회귀 테스트 스위트 구축 (최소 20개 테스트 케이스, 3회 반복 검증 유지)
  - FMS 포털 실시간 대시보드 부하 테스트: 동시 접속자 시뮬레이션으로 WebSocket 연결 안정성 및 Supabase Realtime 응답 지연 측정
  - 에지 케이스 검증 체크리스트 확장: 센서 데이터 누락, 중복 작업 지시서 생성, 네트워크 단절 후 재연결 시나리오를 QA 체크리스트에 추가

- **적용 우선순위:** 중간 — KPI 회귀 테스트는 data-analyst 업그레이드와 병행하여 즉시 착수

1. **일일 스탠드업 자동화**: 각 팀원이 Supabase에 오늘의 작업 상태를 기록하면, data-analyst 에이전트가 자동으로 집계해 translator를 통해 한국어/영어 요약 리포트를 생성하는 파이프라인 구축. 현재 수동 보고 대비 30분/일 절약 예상.
