# AI팀 일일 업그레이드 보고 — 2026-07-09

## 🔍 벤치마킹 인사이트

**출처:** Manufacturing AI Maintenance / Factory Equipment AI Agent / Automotive Predictive Maintenance / Production Workflow Automation (2026 기준)

1. **AI+CMMS 통합이 핵심 차별화 요소** — AI와 CMMS(설비 관리 시스템)가 단일 플랫폼에 통합된 공장은 독립 툴을 사용하는 경우 대비 운영 효율이 15~20% 높음. 별도 툴을 연결하는 수동 작업이 여전히 주요 병목 (oxmaint.com, 2026).

2. **예지정비 도입 현황 및 ROI** — 자동차 부품 제조업체 기준, AI 예지정비 적용 후 OEE 58% → 82% 향상, 비계획 다운타임 71% 감소, 생산손실 $2.9M 회복 사례 확인. 전 세계 제조사의 65%가 2026년 말까지 AI 예지정비 도입 계획 중 (oxmaint.com case study).

3. **알람 피로(Alarm Fatigue)가 최대 실패 원인** — 예지정비 프로젝트의 70%가 단순 알림 과다로 실패. 실행 가능한 인사이트(actionable insight)로의 변환이 필수이며, 이것이 FMS 포털의 대시보드/리포트 설계에 직접 적용됨 (f7i.ai, 2026).

4. **에지 AI + 자연어 인터페이스가 현장 채택율 좌우** — 엣지 컴퓨팅 기반 실시간 이상 탐지와 자연어(Natural Language) 인터랙션이 현장 기술자의 채택 장벽을 낮추는 핵심. 음성 지원 및 모바일 워크오더 업데이트가 표준화 추세 (advancedtech.com, 2026).

5. **AI 에이전트 간 조율(Agent Coordination)이 다음 단계** — 단일 에이전트가 아닌, 신뢰성 에이전트 → 정비 에이전트 → 운영 에이전트가 공유 컨텍스트로 연결되는 멀티에이전트 아키텍처가 2026 제조 선진 공장의 표준으로 부상. 공유 컨텍스트, 명확한 소유권, 에스컬레이션 로직 정의가 필수 (augury.com, decisyon.com).

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 번역 메모리(Translation Memory) 구축: 반복되는 기술 용어(설비명, 불량 코드, KPI 항목 등)를 DSC Mannur 전용 용어집으로 표준화. 한↔영 번역 일관성 확보 및 재번역 비용 제거.
  - 본사 보고서 템플릿 이중 언어화: 주간 KPI 보고, 설비 장애 보고 등 반복 문서를 한/영 병렬 템플릿으로 제작하여 번역 리드타임 단축.
  - AI 초벌 번역 + 검수 워크플로우 도입: Claude/DeepL 초벌 → translator 검수 형태로 전환, 직접 번역 대신 품질 검수에 집중.
- **적용 우선순위:** 🔴 높음 — 본사-인도 커뮤니케이션 오류가 운영 결정에 직접 영향을 미침.

---

### data-analyst
- **개선 제안:**
  - KPI 임계값 기반 자동 알람 설계: 현재 Excel/CSV 기반 수동 분석을 Supabase 트리거 + 알람 규칙으로 전환. "알람 피로" 방지를 위해 임계값 위반 시에만 알림 발송.
  - 트렌드 예측 모듈 추가: 최근 30/60/90일 KPI(OEE, 불량률, 다운타임)에 선형 회귀 또는 이동평균 적용, 다음 주 예측값을 대시보드에 표시.
  - 데이터 파이프라인 문서화: Supabase 테이블 구조, CSV 수집 주기, 집계 로직을 wiki 형태로 정리하여 web-builder/planner와 공유 가능한 단일 진실 공급원(Single Source of Truth) 확보.
- **적용 우선순위:** 🔴 높음 — 예지정비 효과의 70%가 데이터 분석 품질에 달림.

---

### web-builder
- **개선 제안:**
  - Supabase Realtime 구독 활용: 설비 상태·알람 데이터를 폴링 대신 WebSocket 기반 실시간 구독으로 전환하여 FMS 포털의 현황판(Dashboard) 지연 제거.
  - 모바일 퍼스트 워크오더 UI 구현: 현장 기술자가 태블릿/스마트폰으로 작업 지시를 조회·완료 처리할 수 있는 반응형 페이지 우선 개발 (2026 트렌드: 모바일 워크오더 표준화).
  - 에러 상태 및 스켈레톤 UI 강화: 데이터 로딩 실패 시 빈 화면 대신 명확한 에러 메시지와 재시도 버튼 제공. 현장 사용자 신뢰도 향상.
- **적용 우선순위:** 🟡 중간 — 기능 추가보다 현장 사용성 개선이 채택률에 직결.

---

### planner
- **개선 제안:**
  - 알람 계층 설계(Alarm Hierarchy) 명세화: 벤치마킹 결과 "알람 피로"가 최대 실패 요인. Critical / Warning / Info 3단계 알람 체계와 각 레벨의 대응 워크플로우를 기능 명세에 포함.
  - 멀티에이전트 아키텍처 로드맵 수립: 현재 단일 AI 기능에서 → 설비 에이전트 / 정비 에이전트 / 리포트 에이전트 분리 구조로 진화하는 중장기 DB 스키마 및 API 설계 초안 작성.
  - 사용자 역할별 뷰 분리 설계: 현장 기술자(모바일 워크오더), 정비 관리자(KPI 대시보드), 본사(요약 보고서) 3개 페르소나에 맞는 화면 흐름 설계.
- **적용 우선순위:** 🔴 높음 — 명세 품질이 web-builder, data-analyst 모두의 재작업 비율을 결정.

---

### evaluator
- **개선 제안:**
  - 검증 체크리스트 표준화: 매 반복 검증 시 동일 기준(기능 동작, 경계값, 모바일 표시, 한/영 텍스트 일치)을 체크리스트 형태로 고정하여 검증 누락 방지.
  - 회귀 테스트 시나리오 축적: 과거 발견된 버그를 시나리오 라이브러리로 축적, 신규 배포 시 자동 재검증 대상으로 관리.
  - 검증 결과 Supabase 기록: 3회 반복 검증 결과(pass/fail, 발견 이슈, 해결 여부)를 DB에 저장하여 data-analyst가 QA 트렌드를 분석할 수 있도록 연동.
- **적용 우선순위:** 🟡 중간 — 검증 이력 데이터가 쌓일수록 평가 효율 기하급수적 향상.

## 💡 오늘의 효율화 제안

1. **공유 컨텍스트 문서 운영**: planner가 작성한 기능 명세, data-analyst의 KPI 정의, translator의 용어집을 단일 Notion/GitHub Wiki 페이지로 통합 관리. 팀원 간 "서로 다른 버전의 스펙 참조" 문제를 구조적으로 제거. 멀티에이전트 조율 모범 사례(augury.com)에서 공유 컨텍스트가 성공 핵심임을 확인.
