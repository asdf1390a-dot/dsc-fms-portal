# AI팀 일일 업그레이드 보고 — 2026-06-18

## 🔍 벤치마킹 인사이트

1. **Edge AI + 실행 가능한 경보** — 예지 정비 프로젝트의 70%가 '경보 피로(alarm fatigue)' 때문에 실패한다. 클라우드 의존 없이 엣지에서 실시간 이상 감지를 처리하고, 원시 경고 대신 작업 지시(work order) 형태의 실행 가능한 인사이트를 제공해야 한다.

2. **멀티 에이전트 A2A + MCP 구조가 2026년 표준** — 에이전트 간 A2A 프로토콜과 MCP(라이브 데이터 소스 연결)를 결합한 계층형 자동화(모니터링 → 분석/추천 → 스케줄링/실행)가 선도 공장의 공통 패턴이다.

3. **자동차 부품 제조사 OEE 58% → 82% 달성 사례** — AI 예지 정비 도입으로 비계획 다운타임 71% 감소, 생산 능력 $2.9M 회복. 기계 다운타임 35–50% 감소, 유지보수 비용 25–30% 절감 효과가 업계 평균치로 검증됨.

4. **IoT 센서 단가 $0.10–0.80로 하락** — 데이터 인프라 구축의 비용 장벽이 중소 제조업체 수준으로 사라졌다. DSC Mannur 규모에서도 전수 센서 배치가 현실적인 옵션이 됨.

5. **생성형 AI로 드문 고장 시나리오 합성** — 실제로 발생하지 않은 고장 패턴도 합성 데이터셋으로 훈련 가능. 음성·언어 인터페이스로 현장 기술자 관찰 내용을 구조화된 작업 지시로 변환하는 기능이 빠르게 보편화됨.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 한↔영 번역 시 자동차 부품 도메인 용어집(glossary) DB를 Supabase에 구축하여 번역 일관성 확보 (예: OEE, MTBF, 공차(tolerance) 등 기술 용어 표준화)
  - 본사(한국) ↔ 인도 커뮤니케이션에서 문화적 뉘앙스 메모를 번역 결과물에 병기하는 컨텍스트 노트 템플릿 도입
  - 반복 문서(주간 보고, 설비 이상 보고 등) 대상으로 번역 프롬프트 템플릿을 버전 관리하여 품질 일관성 향상
- **적용 우선순위:** 🔴 도메인 용어집 구축 → 🟡 컨텍스트 노트 템플릿 → 🟢 프롬프트 버전 관리

### data-analyst
- **개선 제안:**
  - OEE 실시간 추적 대시보드에 이상 탐지 알림 기능 추가 (단순 임계값 경보 대신 추세 기반 경보로 경보 피로 방지)
  - Supabase에서 교대별·라인별 KPI 자동 집계 뷰(view) 구성 → Excel 수동 작업 제거
  - 예지 정비용 장비 이력 데이터 파이프라인 설계: 센서 데이터 → Supabase → 트렌드 리포트 자동화
- **적용 우선순위:** 🔴 KPI 자동 집계 뷰 → 🟡 이상 탐지 경보 → 🟢 장비 이력 파이프라인

### web-builder
- **개선 제안:**
  - FMS 포털(Next.js 14)에 작업 지시(Work Order) 자동 생성 모듈 추가: 이상 감지 이벤트 → 자동 WO 생성 → 담당자 알림 플로우 구현
  - MCP 패턴으로 Supabase 실시간 구독(Realtime)을 프론트엔드 에이전트와 연결하여 설비 상태를 sub-second 갱신
  - 현장 기술자용 모바일 최적화 UI 강화: PWA 오프라인 지원 + 음성 입력으로 현장 메모 → 구조화된 데이터 변환
- **적용 우선순위:** 🔴 WO 자동 생성 모듈 → 🟡 Realtime 연동 → 🟢 모바일 PWA 최적화

### planner
- **개선 제안:**
  - 멀티 에이전트 아키텍처 설계 도입: 모니터링 에이전트 → 분석/추천 에이전트 → 스케줄링 에이전트 계층별 기능 명세 작성
  - DB 스키마에 장비 이벤트 이력 테이블(`equipment_events`, `maintenance_orders`) 추가 설계하여 예지 정비 기능 확장 준비
  - UI/UX 명세에 "인간-인-루프(human-in-the-loop)" 검토 단계를 명시적으로 포함 — 에이전트 추천을 작업자가 1-click 승인하는 워크플로우 설계
- **적용 우선순위:** 🔴 장비 이벤트 DB 스키마 → 🟡 멀티 에이전트 아키텍처 명세 → 🟢 human-in-the-loop UX 설계

### evaluator
- **개선 제안:**
  - 검증 체크리스트에 "경보 피로 테스트" 항목 추가: 동일 조건에서 경보가 과다 발생하지 않는지 QA 시나리오 포함
  - 3회 반복 검증 사이클에 엣지 케이스(센서 데이터 누락, 오프라인 상태, 동시 다중 이상 등) 시나리오 추가
  - Supabase 데이터 정합성 검증 자동화: 주요 KPI 계산값을 SQL assertion으로 검증하는 테스트 스크립트 구축
- **적용 우선순위:** 🔴 엣지 케이스 시나리오 추가 → 🟡 Supabase 데이터 정합성 자동화 → 🟢 경보 피로 QA 항목 추가

## 💡 오늘의 효율화 제안

1. **도메인 용어집 → 팀 공유 단일 진실 원천(Single Source of Truth) 구축**
   translator가 구축하는 기술 용어집을 Supabase 테이블로 관리하여 data-analyst(KPI 라벨), web-builder(UI 텍스트), planner(명세 문서) 모두가 동일 용어를 참조하도록 연결. 번역 오류와 용어 불일치로 인한 재작업을 팀 전체에서 제거할 수 있음.

2. **일일 보고 자동화 파이프라인 강화**
   현재 수동으로 작성 중인 이 보고서를 data-analyst의 Supabase KPI 뷰와 evaluator의 QA 결과를 자동 집계하여 초안을 생성하는 방향으로 발전 가능. planner가 데이터 연결 명세, web-builder가 API 구현, evaluator가 출력값 검증을 담당하는 분업 구조로 전환 제안.
