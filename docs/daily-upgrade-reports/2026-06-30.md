# AI팀 일일 업그레이드 보고 — 2026-06-30

## 🔍 벤치마킹 인사이트

1. **데이터 기반 없이 AI 도입 불가** — "데이터가 종이 위에 있으면 AI 어시스턴트를 살 수 없다." 디지털 자산 계층 구조, 타입화된 로그, 클라우드 중앙 문서화가 AI 도입의 전제 조건 (Fabrico.io, 2026).

2. **자동차 부품 제조사 OEE 58% → 82% 달성 사례** — AI 예측 정비 + 실시간 OEE 대시보드 도입 후 비계획 다운타임 71% 감소, 생산 용량 $2.9M 회복 (Oxmaint 사례 연구).

3. **멀티에이전트 협업 구조가 핵심** — 신뢰성 에이전트(결함 감지) → 정비 에이전트(일정 예약) → 운영 에이전트(생산 조정)로 이어지는 에이전트 간 핸드오프 설계가 2026년 스마트 팩토리 표준 (Decisyon, IBM, Deloitte).

4. **예지 정비 시장 폭발적 성장** — 2026년 $171억 → 2034년 $974억 (CAGR 24.3%). 유지보수 팀의 2/3가 2026년 말까지 AI 도입 예정이나 실제 완전 구현은 1/3 미만 (iFactoryApp).

5. **엣지 AI + 5G 융합으로 실시간 이상 감지** — Gartner 2025 전략 기술 트렌드: 클라우드 전용 시스템은 데이터 지연으로 이상을 놓치므로 엣지 컴퓨팅이 실시간 이상 감지의 필수 조건. 진동·열·음향 센서 데이터 융합으로 기존 임계값 모니터링 대비 결함을 30~50% 일찍 감지.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 한↔영 번역 시 자동차 부품 제조 도메인 용어집(글로서리) 구축 및 유지관리 — 본사-인도 커뮤니케이션에서 OEE, MTBF, PM(예방 정비) 등 기술 용어 일관성 확보
  - AI 번역 초안 생성 후 도메인 용어 교정 워크플로우 표준화 (DeepL/GPT-4o 초안 → 검수 → 최종 승인 2단계 구조)
  - 자주 사용하는 설비 점검 보고서·작업 지시서 한↔영 템플릿 라이브러리 구축으로 반복 번역 시간 50% 단축
- **적용 우선순위:** 🔴 HIGH — 본사 보고서 오번역은 의사결정 오류로 직결

### data-analyst
- **개선 제안:**
  - Excel/CSV → Supabase 자동 파이프라인 구축: 현장 입력 데이터를 매일 자동으로 Supabase에 업로드하는 스크립트 마련, 수동 업로드 제거
  - OEE 실시간 대시보드에 AI 이상 감지 레이어 추가 — 벤치마크 사례처럼 OEE 트렌드 + 설비별 다운타임 원인 분류 자동화
  - 예지 정비 KPI(MTBF, MTTR, 비계획 다운타임 비율) 추적 모듈 신설 및 주간 트렌드 보고서 자동 생성
- **적용 우선순위:** 🟡 MEDIUM — 데이터 파이프라인 자동화 먼저, 대시보드 확장은 다음 스프린트

### web-builder
- **개선 제안:**
  - Next.js 14 FMS 포털에 실시간 설비 상태 패널 추가 (Supabase Realtime 구독 활용) — 설비별 알람 현황을 WebSocket으로 즉시 반영
  - AI 정비 어시스턴트 채팅 UI 프로토타입 구현 — 기술자가 한국어/영어로 설비 이상 증상을 입력하면 과거 정비 이력 기반으로 조치 방법 제안
  - 모바일 최적화 강화: 현장 기술자가 스마트폰으로 작업 지시서 확인·서명·사진 첨부 가능한 반응형 UI (Fabrico.io 모델 참조)
- **적용 우선순위:** 🟡 MEDIUM — 실시간 패널이 즉각 현장 가치, 채팅 UI는 다음 단계

### planner
- **개선 제안:**
  - 멀티에이전트 아키텍처 설계 시작: 신뢰성 에이전트(결함 감지) → 정비 스케줄러 에이전트 → 생산 계획 에이전트 간 데이터 흐름 및 핸드오프 명세 작성
  - DB 스키마에 설비 센서 데이터 테이블 추가 기획 (진동, 온도, 전력 소비량) — 향후 예지 정비 ML 모델 학습 기반 마련
  - 사용자 역할별 권한 행렬(RBAC) 재검토: 현장 기술자/정비팀/관리자/본사 각각의 접근 범위를 제로트러스트 원칙으로 재정의
- **적용 우선순위:** 🔴 HIGH — 멀티에이전트 명세와 센서 스키마는 web-builder·data-analyst 작업의 선행 조건

### evaluator
- **개선 제안:**
  - QA 체크리스트 자동화: 각 기능 배포 전 Playwright E2E 테스트 시나리오를 표준 템플릿으로 정형화하여 3회 반복 검증 시간 단축
  - 실제 현장 데이터로 검증하는 "프로덕션 미러" 테스트 환경 구축 — Supabase 스테이징 DB에 실제 설비 데이터 샘플을 주기적으로 동기화
  - AI 어시스턴트 응답 품질 평가 루브릭 작성: 정확도·도메인 적합성·언어(한/영) 품질 3개 축으로 정량 평가 기준 정립
- **적용 우선순위:** 🟡 MEDIUM — E2E 자동화가 즉효, 미러 환경은 인프라 협의 후 진행

## 💡 오늘의 효율화 제안

1. **"데이터 정비의 날" 월 1회 운영** — 팀 전원이 참여해 Supabase DB 데이터 품질을 점검하는 정기 세션 도입. 결측값·이상값·중복 레코드를 한 번에 정리. AI 분석 정확도는 데이터 품질에 정비례하므로 이 세션 없이는 어떤 AI 도구도 효과가 반감됨.

2. **translator ↔ planner 조기 참여 관행 확립** — 신기능 기획 단계(DB 스키마 설계 시점)에 translator를 참여시켜 한국 본사 보고 요구사항을 용어 수준에서 반영. 개발 완료 후 번역 교정이 아닌 기획 단계 공동 작업으로 재작업 사이클 제거.
