# AI팀 일일 업그레이드 보고 — 2026-08-03

## 🔍 벤치마킹 인사이트

1. **Agentic AI의 완전 자율 유지보수 루프**: 2026년 최선진 공장에서는 AI 에이전트가 이상 감지 → ERP 부품 재고 조회 → 담당 기술자 스케줄 확인 → 작업지시(WO) 생성까지 인간 개입 없이 자동 완료. 정보 수집에 걸리던 15~30분 지연을 제로로 줄이며 소규모 설비 이슈가 장기 가동 중단으로 번지는 것을 원천 차단.

2. **MES·ERP·SCADA 통합 AI 에이전트**: 공장 바닥의 데이터를 한 곳으로 연결하는 통합 AI 에이전트가 2026년 업계 표준으로 자리잡음. MES, ERP, SCADA, PLC, IoT 센서 데이터를 실시간 분석해 OEE 개선·스크랩 감소·공급망 의사결정을 동시에 지원. 단일 시스템이 아닌 다계층 통합이 핵심.

3. **자동차 부품 예지보전 시장 가속화**: Bosch가 2026년 3월 AI 예지보전 전문 스타트업 Uptake Technologies를 인수하며 자동차 부품 제조사 대상 AI 예지보전 시장 경쟁 본격화. ECU 및 센서 데이터 분석으로 고장 직전 패턴을 감지하는 AI fault tree가 주니어 기술자 진단 시간을 대폭 단축.

4. **자연어 워크플로우 생성(NL-to-Workflow)**: 2026년 No-Code AI 플랫폼은 담당자가 자연어로 원하는 프로세스를 설명하면 AI가 워크플로우 초안을 자동 생성하는 수준에 도달. 과거 수주 걸리던 자동화 구축이 수 시간으로 단축되어 비개발자도 워크플로우를 직접 설계·배포 가능.

5. **디지털 트윈으로 "가상 공장" 시뮬레이션**: 실시간 센서 데이터를 수신하는 AI 기반 Digital Twin이 공장 관리자에게 "what-if" 시나리오 시뮬레이션 도구를 제공. 실제 생산에 영향을 주지 않고 설정 변경·공정 최적화를 가상으로 테스트한 뒤 적용하는 방식이 확산 중.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 본사-인도 간 기술 문서(사양서, 작업지시서, 품질 보고서)에 대해 자동차 부품 제조 도메인 특화 번역 파이프라인 구축: Claude API + 사내 용어집 후처리 조합으로 일관성 확보
  - AI fault tree 진단 결과 리포트처럼 구조화된 기술 문서는 템플릿 기반 번역 방식(field-by-field)을 도입하여 자유 문장 번역보다 정확도·속도 향상
  - 번역 결과에 대한 신뢰도 점수(confidence score)를 자동 표시하는 기능 추가: 점수 낮은 항목만 사람이 검토하는 "human-in-the-loop" 최소화 전략 적용
- **적용 우선순위:** 🔴 도메인 특화 파이프라인 → 🟡 템플릿 기반 번역 도입 → 🟢 신뢰도 점수 자동화

### data-analyst
- **개선 제안:**
  - MES·ERP 데이터를 Supabase로 실시간 동기화하는 ETL 파이프라인 구성: 현재 수동 Excel 업로드 방식을 폐지하고 자동화된 데이터 흐름 구축
  - OEE(설비 종합 효율) 지표를 시계열로 저장·분석하여 스크랩 발생 직전의 공정 패턴을 ML 이상 감지 모델로 학습: "왜 스크랩이 증가했는가"를 데이터로 설명 가능하게 만들기
  - 경영진 주간 보고에 "AI 자동 요약 코멘트" 섹션 추가: Claude API를 통해 KPI 변화 원인과 권고 조치를 자연어로 생성하여 리포트 작성 시간 80% 절감 목표
- **적용 우선순위:** 🔴 자동 ETL 파이프라인 → 🟡 OEE 이상 감지 모델 → 🟢 AI 자동 요약 섹션

### web-builder
- **개선 제안:**
  - FMS 포털에 Agentic AI WO(작업지시) 자동 생성 플로우 구현: 센서 이상 감지 이벤트 → Supabase 함수(Edge Function) 트리거 → WO 자동 생성 → 담당자 푸시 알림까지 인간 개입 없이 처리
  - 설비 상세 페이지에 "AI fault tree" 뷰 추가: 현재 장애 증상을 입력하면 Claude API가 가장 가능성 높은 원인 3가지를 단계별로 제시하는 인터랙티브 진단 UI 구현
  - Next.js 14 Server Actions와 Supabase Realtime을 조합해 생산 현황 대시보드의 데이터 새로고침 없이 실시간 수치 갱신 구현 (polling 방식 제거)
- **적용 우선순위:** 🔴 Agentic WO 자동 생성 플로우 → 🟡 AI fault tree 진단 UI → 🟢 Realtime 대시보드

### planner
- **개선 제안:**
  - Digital Twin 개념을 FMS 포털에 단계적으로 도입하기 위한 로드맵 작성: Phase 1(실시간 설비 상태 시각화) → Phase 2(센서 이력 기반 시뮬레이션) → Phase 3(AI 추천 공정 최적화)
  - Agentic AI 워크플로우의 DB 스키마 설계: 에이전트 실행 이력, 자동 생성된 WO, 각 단계별 의사결정 근거를 감사 추적(audit trail) 가능한 구조로 Supabase에 정의
  - 자연어 워크플로우 생성 기능을 위한 UI 명세 작성: 현장 담당자가 "이 설비가 진동 이상일 때 WO를 생성하고 반장에게 알려줘"라고 입력하면 자동화 규칙이 만들어지는 플로우 설계
- **적용 우선순위:** 🔴 Digital Twin 도입 로드맵 → 🟡 Agentic AI DB 스키마 설계 → 🟢 자연어 워크플로우 UI 명세

### evaluator
- **개선 제안:**
  - Agentic WO 자동 생성 플로우 검증에 특화된 E2E 테스트 시나리오 작성: 센서 이상 신호 Mock → WO 생성 확인 → 알림 발송 확인 → 상태 업데이트 확인의 전체 체인을 Playwright로 자동 검증
  - 3회 반복 검증 결과를 Supabase `qa_verification_logs` 테이블에 구조화 저장: 라운드별 통과/실패 항목, 소요 시간, 검증자(인간/AI) 구분을 필드로 정의하여 품질 이력 데이터 축적
  - AI 기반 회귀 테스트 도입: 신규 기능 배포 후 Claude API를 활용해 기능 명세 문서와 실제 화면 스크린샷을 비교 분석하여 의도치 않은 UI 변경 자동 감지
- **적용 우선순위:** 🔴 Agentic WO E2E 테스트 시나리오 → 🟡 검증 이력 DB 설계 → 🟢 AI 회귀 테스트 도입

## 💡 오늘의 효율화 제안

1. **"자연어 자동화 규칙" 파일럿 운영**: 2026년 업계 흐름에 맞춰 planner가 자연어로 자동화 규칙을 정의하면, web-builder가 이를 Supabase Edge Function + 알림 로직으로 구현하는 소규모 파일럿을 이번 주 안에 시작할 것을 제안. 예: "밀링머신 진동이 X 이상이면 WO 생성 후 반장에게 문자 발송" — 이 하나의 규칙을 완성하면 팀 전체가 Agentic AI 워크플로우를 실제로 경험할 수 있음.

2. **MES→Supabase 자동 데이터 흐름 우선 구축**: 현재 팀의 KPI 분석, AI 이상 감지, Digital Twin 등 모든 고도화 기능의 전제 조건은 "신뢰할 수 있는 실시간 데이터"임. data-analyst와 web-builder가 협력해 MES 데이터를 Supabase로 자동 동기화하는 파이프라인을 최우선으로 완성하면, 나머지 AI 기능 개발 속도가 전반적으로 빨라짐.
