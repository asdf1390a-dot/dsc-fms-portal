# AI팀 일일 업그레이드 보고 — 2026-06-19

## 🔍 벤치마킹 인사이트

1. **알람 피로(Alarm Fatigue) 회피 설계**: 예지보전 프로젝트의 70%가 실패하는 주요 원인은 단순 알림 과잉 발생이다. 실용적 인사이트가 아닌 알림만 쏟아내는 시스템은 무용지물 — DSC FMS 포털도 임계값 기반 알림보다 맥락 기반 우선순위 추천(recommendation) 방식이 필요.

2. **Edge AI + 실시간 데이터 연계**: 2026년 기준 선도 공장들은 IIoT 센서(진동·온도·전류) + Edge AI로 장비 이상을 **2~4주 전** 예측, OEE를 최대 82%까지 끌어올리고 비계획 다운타임을 71% 절감. Supabase 실시간 구독과 Next.js 연동이 이 아키텍처와 직접 호환됨.

3. **멀티 에이전트 조율 구조**: 2026년 산업용 AI 배포의 핵심은 단일 AI가 아닌 **전문 에이전트 간 협업** — 데이터 수집 에이전트, 분석 에이전트, 작업 지시 에이전트가 계층적으로 조율됨. 현재 팀 구성(translator/analyst/web-builder/planner/evaluator)이 이 구조와 정렬 가능.

4. **자연어 인터페이스의 현장 적용**: 기술자가 음성·텍스트로 관찰 내용을 입력하면 AI가 구조화된 작업 지시서(Work Order)를 자동 생성하는 NLP 워크플로우가 표준화 추세. 본사(한국)↔인도 현장 간 언어 장벽을 AI 번역과 결합하면 도입 효과 극대화.

5. **예지보전 시장 급성장 + 자동차 부품 ROI 입증**: 예지보전 시장은 2026년 $171억 → 2034년 $974억(CAGR 24.3%). 자동차 부품 제조사 실제 사례: AI 예지보전 도입 14개월 만에 OEE 82% 달성, $290만 생산 용량 회복 — DSC Mannur와 동일 업종의 검증된 ROI.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 현장 기술 용어(Work Order, OEE, MTTR, Breakdown 등) 특화 용어집(glossary) DB를 Supabase에 구축하고 번역 시 자동 참조하도록 워크플로우 개선
  - 한국 본사 보고서 → 영어 현장 지시로 번역 시, 인도 현지 관용 표현(Indlish) 패턴을 학습하여 현장 수용성 높이기
  - 번역 완료 후 data-analyst에게 KPI 수치 일관성(단위·소수점·날짜 포맷) 교차검증 요청하는 체크포인트 추가
- **적용 우선순위:** 🔴 High — 본사-현장 커뮤니케이션 오류가 가장 빠른 ROI 저하 요인

### data-analyst
- **개선 제안:**
  - OEE(가용률×성능률×품질률) 자동 계산 대시보드를 Supabase view + Next.js 차트로 구현, 현재 Excel 수동 집계를 대체
  - 트렌드 이상 감지(anomaly detection) 로직 추가: 최근 7일 이동평균 대비 ±2σ 초과 시 자동 플래그 — 알람 피로 방지를 위해 임계값은 상위 5개 이슈로 제한
  - 예지보전 데이터(진동·온도·전류)를 Supabase 테이블로 수신하는 파이프라인 설계 참여, 분석 가능 형태로 정규화 명세 작성
- **적용 우선순위:** 🔴 High — OEE 자동화 대시보드는 2주 이내 MVP 가능

### web-builder
- **개선 제안:**
  - Next.js 14 App Router + Supabase Realtime으로 장비 상태 **실시간 업데이트** 화면 구현(현재 polling 방식이면 WebSocket 구독으로 전환)
  - 작업 지시서(Work Order) 자연어 입력 폼 추가: 현장 기술자가 한/영 혼용 텍스트 입력 → translator 에이전트 API 경유 → 구조화된 WO 자동 생성
  - 모바일 PWA 최적화: 인도 현장 태블릿/핸드폰 환경(저사양, 불안정 네트워크) 대응을 위한 오프라인 캐시 + 낙관적 업데이트 패턴 적용
- **적용 우선순위:** 🟡 Medium — Realtime 전환이 선행, WO 폼은 planner 명세 후 착수

### planner
- **개선 제안:**
  - **3-Tier 에이전트 아키텍처** 설계 문서 작성: (1) 모니터링·알림, (2) 분석·추천, (3) 작업 스케줄링 — 각 티어별 DB 스키마와 API 계약 정의
  - 신규 기능 명세 시 "알람 피로 방지 원칙" 체크리스트를 필수 포함 — 알림 우선순위 로직, 최대 동시 알림 수, 에스컬레이션 규칙을 명세에 명기
  - 예지보전 모듈 UI/UX 와이어프레임 작성: 장비 카드 → 이상 지표 드릴다운 → 추천 조치 → WO 생성 흐름을 5단계 화면으로 설계
- **적용 우선순위:** 🔴 High — 3-Tier 아키텍처 설계가 모든 팀원의 다음 스프린트 블로커

### evaluator
- **개선 제안:**
  - 검증 체크리스트에 **다국어 일관성 항목** 추가: 한국어 UI 텍스트, 영어 API 응답, 현장 보고서 용어가 glossary DB와 일치하는지 3회 순환 검증
  - 실시간 데이터 파이프라인 QA 시나리오 추가: 센서 데이터 누락(null), 극단값(outlier), 타임스탬프 불일치 케이스를 자동 테스트 스크립트로 커버
  - 예지보전 알고리즘 출력 검증 기준 정의: 추천 정밀도(precision) ≥80%, 오탐(false positive)율 ≤15% — 이 기준을 evaluator 판단 기준으로 표준화
- **적용 우선순위:** 🟡 Medium — 다국어 일관성 검증은 즉시 적용, 파이프라인 QA는 web-builder 구현 후

## 💡 오늘의 효율화 제안

1. **팀 내 지식 루프 자동화**: translator → data-analyst → evaluator 순서로 산출물이 순환 검증되는 현재 구조에 **Supabase 상태 테이블**을 추가하여, 각 에이전트가 완료 시 상태를 업데이트하고 다음 에이전트가 자동으로 픽업하도록 개선. planner가 이 스키마를 이번 주 설계하면 web-builder가 다음 주 구현 가능.

2. **"주간 예지보전 인사이트" 리포트 자동화**: data-analyst가 매주 월요일 자동 생성하는 OEE·다운타임·이상 감지 요약 리포트를 Next.js API Route로 트리거, PDF 또는 Slack/이메일로 본사에 자동 발송. translator가 한↔영 버전을 동시 생성. 2주 내 MVP 가능.
