# AI팀 일일 업그레이드 보고 — 2026-07-22

## 🔍 벤치마킹 인사이트

1. **Agentic AI로의 전환**: 2026년 제조 유지보수는 단순 이상 감지를 넘어 "Agentic AI"로 진화 중 — 이상 탐지 후 ERP에서 부품 재고 확인, 기술자 배정, 작업 지시서 자동 생성까지 인간 개입 없이 실행. 공장 다운타임 25~40% 감소 보고.

2. **자동차 부품 제조 예측 정비 ROI**: 자동차 부품 업계에서 AI 예측 정비 도입 시 계획외 정지 45% 감소, 유지보수 비용 28% 절감, 설비 가동률 99.7% 달성 사례 보고. 전체 프로그램 ROI는 단계적 적용 기준 3~6개월 내 실현.

3. **멀티 에이전트 상호 조정**: 신뢰성 에이전트 → 유지보수 에이전트 → 운영 에이전트 간 맥락 공유·명확한 책임 분리·에스컬레이션 로직이 핵심. 단일 에이전트보다 다중 에이전트 협업 아키텍처가 공장 전 영역 커버에 유리.

4. **워크플로우 AI 자동화 확산**: 2025년 스마트 제조 시장 3,940억 달러 규모, 연 15% 성장. AI 기반 품질검사·재고관리·생산 스케줄링 자동화가 현장 표준으로 정착 중. n8n, SymphonyAI 등 로우코드 플랫폼이 중소 제조사 진입 장벽 낮춤.

5. **AI 유지보수 어시스턴트 "Digital Mentor" 개념**: 주니어 기술자가 자연어 질문만으로 공장 전체의 집단 지식에 접근 가능한 시대. 정보 수집에 소요되던 15~30분 지연이 수 초로 단축 — 소규모 설비 이상이 장시간 생산 중단으로 확대되는 악순환 차단.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 본사(한국) ↔ 인도 현장 간 기술 문서 번역 시 자동차 부품 도메인 전문 용어 사전(glossary) 구축 및 번역 메모리(TM) 데이터베이스화 — 반복 용어 일관성 보장.
  - AI 유지보수 보고서·KPI 요약본의 영↔한 번역 속도 향상을 위해 Claude API 기반 번역 템플릿 도입 (도메인 프롬프트 사전 설정).
  - 현장 긴급 소통용 짧은 슬랙 메시지 번역과 공식 문서 번역을 구분한 투트랙 워크플로우 운영.
- **적용 우선순위:** 높음 — 본사-인도 커뮤니케이션 지연이 유지보수 결정 속도에 직결.

### data-analyst
- **개선 제안:**
  - Supabase KPI 데이터에 예측 정비 모델 연결 시도 — 설비 가동률·고장 빈도 트렌드를 기반으로 다음 주 고장 위험 장비 상위 3개 자동 산출.
  - Excel/CSV 수작업 집계를 Supabase 뷰(View) + 자동 새로고침 대시보드로 대체, 데이터 최신성 보장.
  - 자동차 부품 업계 벤치마크(다운타임 목표 <0.3%, 유지보수 비용 절감 28% 기준선)와 현재 공장 지표 비교 리포트 주 1회 정례화.
- **적용 우선순위:** 높음 — 예측 분석 전환이 현재 분기 핵심 과제.

### web-builder
- **개선 제안:**
  - FMS 포털 내 "AI 정비 어시스턴트" 채팅 위젯 추가 검토 — 기술자가 설비 ID 입력 시 관련 이력·권장 점검 항목·부품 재고 상태를 자연어로 반환하는 기능 (Next.js API Route + Claude API 연동).
  - Supabase Realtime 구독을 활용한 설비 알림 실시간 표시 — 페이지 새로고침 없이 이상 징후 즉시 UI 반영.
  - 모바일 현장 접근성 강화: PWA(Progressive Web App) 전환 또는 반응형 레이아웃 최적화로 태블릿·스마트폰 현장 사용 지원.
- **적용 우선순위:** 중간 — 실시간 알림은 단기, 채팅 위젯은 다음 스프린트 목표.

### planner
- **개선 제안:**
  - 멀티 에이전트 아키텍처 설계 도입 검토: 현재 단일 AI 기능 요청을 "신뢰성 에이전트 → 유지보수 에이전트 → 운영 에이전트" 3단계 파이프라인으로 재설계하는 기능 명세 작성.
  - DB 스키마에 `maintenance_events` 테이블 추가 계획 수립 — 설비 고장 로그, 수리 이력, 부품 교체 기록을 구조화하여 향후 예측 모델 학습 데이터로 활용.
  - UI/UX 설계 시 "정보 수집 지연 제거" 원칙 적용 — 기술자가 현장에서 3클릭 이내로 설비 상태·작업 지시서·부품 재고에 접근 가능한 네비게이션 플로우 설계.
- **적용 우선순위:** 높음 — 스키마 설계가 data-analyst·web-builder 작업의 선행 조건.

### evaluator
- **개선 제안:**
  - 예측 정비 기능 검증 시 "섀도우 런(shadow run)" 방법론 채택 — 실제 운영과 병행하여 AI 제안값과 실제 결과를 3회 이상 비교 후 정식 반영.
  - 자동화 워크플로우의 QA 체크리스트에 "데이터 최신성 검증" 항목 추가 — Supabase 데이터 갱신 시간이 리포트 생성 시간보다 앞서는지 확인.
  - 번역 품질 검증 시 도메인 전문가(현장 엔지니어) 1인 포함한 3자 검토 프로세스 표준화 (번역→내부 검토→현장 확인).
- **적용 우선순위:** 중간 — 섀도우 런 프로세스는 새 기능 배포 전 필수 단계로 즉시 문서화.
