# AI팀 일일 업그레이드 보고 — 2026-06-02

## 🔍 벤치마킹 인사이트

1. **AI 에이전트가 '어시스턴트'에서 '자율 실행자'로 전환**: 2026년 제조업 AI의 가장 큰 패러다임 전환은 단순 응답형 어시스턴트에서 목표 설정 → 다단계 계획 수립 → 도구 실행을 스스로 수행하는 Agentic AI로의 이동. NVIDIA Jensen Huang: "Agentic AI는 단순 자동화가 아니라 추론하는 자동화." 제조업에서 2026년까지 루틴 정비 업무 40~60%가 AI 에이전트에 의해 end-to-end 자동화될 전망. (출처: dataiku.com, definitiontech.co)

2. **자동차 부품 제조업체 AI 예측정비 정량 성과**: 업계 평균 비계획 다운타임 35~50% 감소, 정비 비용 10~40% 절감. MidWest Automotive Components 사례: AI 도입 후 주간 비계획 다운타임 4.7시간 → 0.8시간(87% 개선), 연간 비용 절감 $2.3M. Volvo·Mack Trucks: 실시간 데이터 분석으로 진단 시간 70% 단축, 수리 시간 25% 감소. (출처: masterofcode.com, oxmaint.com)

3. **6-Layer 프로덕션급 AI 에이전트 아키텍처**: 성공적인 제조 AI 에이전트는 ① Model(LLM) ② Tools(MES/ERP/센서 연동 함수) ③ Retrieval(SOP·작업이력 벡터스토어) ④ Orchestration(루프·재시도·Human-in-the-Loop) ⑤ Observability(모든 프롬프트·도구호출·비용 로깅) ⑥ Evaluation(회귀 테스트 스위트) 6개 레이어로 구성. DSC FMS 포털 설계에 직접 적용 가능한 레퍼런스 아키텍처. (출처: mindstudio.ai, deloitte.com)

4. **No-Code/Low-Code AI 워크플로 자동화 성숙**: 2026년 No-Code 자동화 플랫폼이 커스텀 개발 수준으로 성숙. 자연어로 워크플로를 기술하면 AI가 자동 생성하는 기능 실용화. 기업 72%가 최소 1개 비즈니스 기능에 AI 도입(2024년 55%→2024년 72% 급증). Gartner 예측: 2026년까지 조직의 20%가 관리 업무를 AI로 자동화. (출처: cflowapps.com, kissflow.com)

5. **"Start Narrow" 전략이 유일한 검증된 확장 경로**: 2026년 성공적인 AI 생산 배포는 예외 없이 단일 워크플로에서 시작해 60~90일 내 가치 증명 후 확장. 거버넌스(인간 감독 대시보드, 컴플라이언스 체크, 안전 가이드레일)를 먼저 구축하는 것이 파일럿을 프로덕션으로 전환하는 핵심 요건. (출처: mindstudio.ai/blog/ai-agent-governance, weforum.org)

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - **자동차 부품 도메인 특화 용어 감지 강화**: 번역 요청 수신 시 "OEE", "MTBF", "MTTR", "작업지시서(Work Order)", "비계획 다운타임(Unplanned Downtime)" 등 DSC 핵심 기술 용어를 자동 감지하여 Supabase `term_glossary` 테이블과 대조 후 표준어 적용. 오역 리스크를 사전 차단.
  - **본사-현장 긴급도 레벨 분류 체계 도입**: 번역 요청을 긴급(Critical·당일), 일반(Standard·24시간), 검토(Review·48시간) 3단계로 분류하는 수신 양식 표준화. Agentic AI 트렌드에 맞춰 긴급 번역은 AI 초안 즉시 제공 → 인간 검토 워크플로로 전환.
  - **번역 품질 피드백 루프 구축**: 본사 수신 확인 후 번역 수정 요청 발생 시 Supabase `translation_feedback` 테이블에 기록 → 주간 오류 패턴 분석 → 용어집 자동 업데이트 파이프라인.
- **적용 우선순위:** 🔴 긴급도 레벨 분류 양식 → 🟡 용어 자동 감지 연동 → 🟢 피드백 루프 DB 구축

### data-analyst
- **개선 제안:**
  - **실시간 예측 정비 KPI 대시보드**: AI 예측정비 도입 성과 추적을 위해 `비계획 다운타임`, `OEE`, `MTBF`, `MTTR` 4개 핵심 지표를 Supabase Realtime 뷰로 전환. Excel 수작업 집계 완전 제거. 전주 대비 편차 ±15% 초과 시 자동 알림 트리거.
  - **자동차 부품 업종 벤치마크 비교 분석**: MidWest Automotive(다운타임 87% 개선), Volvo Trucks(진단시간 70% 단축) 등 업계 레퍼런스 수치를 DSC Mannur 실적과 나란히 비교하는 갭 분석 리포트 월 1회 자동 생성.
  - **이상값 조기 감지 알림 고도화**: 현재 사후 분석 중심에서 패턴 기반 사전 경고로 전환. 동일 장비의 연속 3회 이상 소규모 이상값이 감지되면 예방정비 권고 알림 발송.
- **적용 우선순위:** 🔴 Realtime KPI 뷰 전환 → 🟡 이상값 패턴 알림 → 🟢 업계 벤치마크 갭 분석 자동화

### web-builder
- **개선 제안:**
  - **6-Layer 에이전트 아키텍처 기반 FMS 포털 Observability 레이어 추가**: AI 에이전트가 생성하는 모든 작업지시서·번역 요청·KPI 보고서의 프롬프트, 도구 호출, 응답, 처리시간을 `ai_activity_log` 테이블에 기록. Next.js 14 Server Actions로 구현하고 관리자 대시보드에 실시간 노출.
  - **장비 건강도(Health Score) UI 컴포넌트 완성**: 센서 데이터 집계 → 0~100 점수화 → 색상 코딩(🟢 80+, 🟡 50~79, 🔴 49-) 카드형 컴포넌트. Supabase Realtime 구독으로 상태 변경 즉시 반영. No-Code 플랫폼 성숙 트렌드 대응으로 비개발자도 설정 가능한 임계값 UI 제공.
  - **Human-in-the-Loop 승인 UI 구현**: AI가 생성한 작업지시서에 '승인 / 수정 요청 / 반려' 3단계 버튼 추가. `approval_status`, `approved_by`, `approved_at` 필드 표준화. 승인 대기 건수를 헤더 배지로 표시.
- **적용 우선순위:** 🔴 Human-in-the-Loop 승인 UI → 🟡 Health Score 컴포넌트 → 🟢 Observability 로그 대시보드

### planner
- **개선 제안:**
  - **Agentic AI 6-Layer 아키텍처를 FMS 포털 설계 표준으로 채택**: 신규 기능 명세 시 Model / Tools / Retrieval / Orchestration / Observability / Evaluation 6개 레이어를 체크리스트로 명시. 누락 레이어는 MVP 이후 단계로 명확히 분리하여 기술 부채 방지.
  - **"Start Narrow 60일 MVP" 기능 명세 템플릿 도입**: 모든 신규 기능에 ① 60일 내 측정 가능한 성과 지표 ② 최소 기능 범위(MVP) ③ 확장 단계 로드맵을 필수 항목으로 포함. 업계 검증된 단계적 확장 전략 내재화.
  - **멀티에이전트 협업 시나리오 시퀀스 다이어그램 문서화**: translator → data-analyst → web-builder 연동 플로우, Human-in-the-Loop 체크포인트 위치, 장애 시 폴백 시나리오를 기능 명세서에 표준 포함.
- **적용 우선순위:** 🔴 6-Layer 설계 체크리스트 표준화 → 🟡 60일 MVP 명세 템플릿 → 🟢 멀티에이전트 시퀀스 문서화

### evaluator
- **개선 제안:**
  - **AI 출력 검증 체크리스트 신설**: 기존 기능 검증(3회 반복) 외에 AI 생성 결과물(작업지시서, 번역문, KPI 리포트) 전용 검증 기준 수립. 샘플링 비율(예: 전체 AI 출력의 20% 무작위 검토), 정확도 허용 오차(±5%), 에스컬레이션 기준 명문화.
  - **회귀 테스트 자동화 파이프라인 구축**: 신규 배포 시 이전 스프린트의 핵심 기능(Health Score 계산, 작업지시서 생성, KPI 집계)이 정상 동작하는지 자동 확인. Supabase Edge Functions 또는 GitHub Actions를 활용한 배포 후 자동 검증.
  - **QA 결과 트렌드 분석**: 검증 결과를 `qa_log(id, feature, test_round, result, error_type, resolved_at)` 테이블에 기록. 주간 오류 유형별 빈도 분석 → 반복 오류 패턴 식별 → 근본 원인 제거 우선순위 도출.
- **적용 우선순위:** 🔴 AI 출력 전용 검증 기준 수립 → 🟡 회귀 테스트 자동화 → 🟢 QA 트렌드 로그 DB 구조화

## 💡 오늘의 효율화 제안

1. **Observability 우선 전략 — 로깅 인프라를 먼저 깐다**: 업계 사례에서 공통적으로 확인된 것은, AI 에이전트가 프로덕션에서 신뢰받으려면 모든 결정의 추적 가능성이 필수라는 점. 오늘 당장 `ai_activity_log` 테이블(agent, action, input_summary, output_summary, duration_ms, created_at)을 Supabase에 생성하고 web-builder가 Server Actions에서 자동 기록하도록 연결하면, 이후 evaluator의 QA·data-analyst의 성과 분석·planner의 아키텍처 의사결정 모두 이 단일 테이블에서 파생 가능.

2. **팀 내 "60일 가치 증명" 사이클 도입**: 업계 검증된 "Start Narrow" 원칙을 팀 운영 방식에 적용. 매 스프린트 시작 시 planner가 "60일 후 어떤 수치가 개선됐는지 측정할 수 있는가?"를 명세에 명시하고, data-analyst가 기준값(baseline)을 사전 기록하고, evaluator가 60일 후 검증하는 3-way 책임 구조. 이 루틴이 정착되면 벤치마킹 인사이트가 실제 성과 지표 개선으로 연결되는 추적 가능한 파이프라인이 됨.
