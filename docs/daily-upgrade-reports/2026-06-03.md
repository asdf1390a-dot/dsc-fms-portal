# AI팀 일일 업그레이드 보고 — 2026-06-03

## 🔍 벤치마킹 인사이트

1. **Agentic AI 전환 가속** — 2026년 선도 제조사들은 루틴 정비 작업의 40~60%를 AI 에이전트로 완전 자동화(작업 지시 생성 → 기술자 배치 → 부품 발주까지). 인간은 단계가 아닌 결과를 감독하는 구조로 이동 중.

2. **예측 정비 ROI 확인** — 자동차 부품 제조 분야에서 AI 예측 정비 도입 시 비계획 다운타임 25~40% 감소, 글로벌 47%의 제조사가 이미 도입. Tractian·UpKeep Nova 등 도구가 회전체 장비 고장 예측·자동 작업지시 생성을 실용화.

3. **No-Code/자연어 워크플로우 빌더 주류화** — 비기술 사용자도 자연어로 업무 흐름을 설명하면 AI가 자동으로 워크플로우를 구성. 생산 현장 디지털 트윈과 결합해 "what-if 시나리오" 시뮬레이션이 표준 관행으로 자리잡는 중.

4. **Generative AI 현장 코파일럿** — 기술자가 수리 시점에 500페이지 OEM 매뉴얼을 즉시 조회·요약받고, 수리 이력·부품 추천·트러블슈팅 순서를 단일 인터페이스에서 제공받는 "현장 AI 코파일럿"이 2026년 표준화.

5. **거버넌스·인간 감독 필수화** — 자율 AI 에이전트 확산에 따라 인간 감독 대시보드, 컴플라이언스 체크 자동화, 에이전트 행동 감사 로그가 제조 AI 도입의 필수 요건으로 부상.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 번역 메모리(TM) DB를 Supabase에 구축해 기존 번역 이력을 재사용 가능한 용어집으로 누적 관리
  - DSC Mannur 공장 특화 도메인 용어집(부품명, 공정 코드, 품질 기준 약어) 표준화 문서 작성 및 AI 프롬프트에 컨텍스트로 주입
  - 본사↔인도 이메일·보고서 번역 시 AI 초안 → 검토 → 승인의 3단계 파이프라인 정식화
- **적용 우선순위:** 🔴 High — 용어 불일치로 인한 커뮤니케이션 오류가 생산 결정에 직결

### data-analyst
- **개선 제안:**
  - Supabase Edge Function으로 KPI 자동 집계 스케줄러 구현 (일별 다운타임, OEE, 불량률 자동 계산)
  - Excel 수동 집계 → Supabase 뷰(View) 기반 실시간 대시보드로 전환, 데이터 신선도 확보
  - 이상치 탐지 알림 추가: KPI가 임계값(예: 불량률 >2%) 벗어날 시 Slack/이메일 자동 알림
- **적용 우선순위:** 🔴 High — 수동 집계 지연이 의사결정 타이밍을 놓치게 하는 핵심 병목

### web-builder
- **개선 제안:**
  - Next.js 14 App Router의 Server Actions를 활용해 폼 제출·데이터 뮤테이션 패턴 표준화, 클라이언트 번들 감소
  - Supabase Realtime 구독으로 설비 상태·작업 지시 변경을 UI에 즉시 반영 (폴링 제거)
  - 모바일 현장 작업자를 위한 PWA 오프라인 모드 지원 — 네트워크 불안정 공장 환경 대응
- **적용 우선순위:** 🟡 Medium — 현장 접근성 향상이 데이터 입력 정확도·속도에 직접 영향

### planner
- **개선 제안:**
  - 기능 명세 작성 시 "AI 에이전트 트리거 조건"을 명시적 필드로 추가 (어떤 이벤트가 자동화를 발동하는가)
  - DB 스키마 설계에 audit_log 테이블 패턴 표준화 — 모든 변경 이력을 created_by·changed_at·diff 형태로 기록
  - 신규 기능 설계 전 디지털 트윈 시뮬레이션 단계 도입: UI 와이어프레임과 함께 "데이터 흐름 다이어그램" 병행 작성
- **적용 우선순위:** 🟡 Medium — 명세 누락이 web-builder 재작업의 주요 원인

### evaluator
- **개선 제안:**
  - Playwright 기반 E2E 자동화 테스트 스위트를 CI/CD에 연결해 매 PR마다 회귀 검증 자동 실행
  - 검증 체크리스트를 기능·성능·보안·접근성 4개 축으로 구조화, 각 축별 최소 통과 기준 명문화
  - 3회 반복 검증 사이클을 "발견→재현→수정확인" 형태로 이슈 트래킹 시스템(GitHub Issues)과 연동
- **적용 우선순위:** 🔴 High — 자동화 없이 수동 검증만으로는 배포 속도와 품질 동시 유지 불가
