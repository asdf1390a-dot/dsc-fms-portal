# AI팀 일일 업그레이드 보고 — 2026-07-31

## 🔍 벤치마킹 인사이트

1. **AI 유지보수 코파일럿(Digital Mentor) 실용화** — 최신 CMMS 플랫폼에 내장된 AI 챗봇이 자연어로 장비 이력·정비 절차·부품 재고를 즉시 답변, 기존에 15–30분 걸리던 정보 수집 지연을 수 초로 단축. Siemens Industrial Copilot(MS 협력)과 Fabrico Assistant가 대표 사례. 정보 접근성 개선 자체가 생산 중단 시간 단축으로 직결됨.

2. **자동차 부품 AI 예측 정비 정량 성과** — AI 예측 유지보수를 도입한 선도 자동차 제조사는 비계획 중단 45% 감소, 유지보수 비용 28% 절감, 조립 라인 가용률 99.7% 달성. Volvo/Mack Trucks는 장애 진단 시간 70% 단축, 수리 시간 25% 감소를 실증 보고. 글로벌 자동차 예측 유지보수 시장은 2030년까지 $167.5억 규모로 성장 전망.

3. **디지털 트윈(Digital Twin) 양산 확대** — 실시간 센서 데이터를 공급받는 AI 기반 공장 가상 복제본이 양산에 진입. 관리자가 실제 라인을 건드리지 않고 공정 변경 시뮬레이션·병목 탐지·"what-if" 시나리오 분석 가능. 제조 AI 워크플로우 자동화의 핵심 기반 기술로 부상.

4. **노코드 자연어 워크플로우 자동화 성숙** — 2026년 현재 비기술 사용자가 업무 과정을 평문으로 설명하면 AI가 자동화 워크플로우 초안을 즉시 생성. "아이디어 → 프로덕션" 기간이 수 주에서 수 시간으로 단축. 반복성이 높은 단일 프로세스 자동화 시 30–60일 내 ROI 달성 사례가 다수.

5. **자동차 AI 정비 시장 구조 변화** — 글로벌 제조사의 47%가 이미 예측 유지보수 기술 도입 완료. AI 기반 자동화가 불규칙한 중단(비계획 다운타임)을 35–50% 줄이고 유지보수 비용을 10–40% 낮추는 효과가 산업 전반에서 재현 가능한 수준으로 표준화됨.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 자동차 부품 제조 도메인 한↔영 용어 사전에 "정비 코파일럿" 계열 신조어(Digital Mentor, Copilot, Work Order, OEE 등) 추가 — Siemens·Bosch 등 글로벌 표준 표기 기준으로 정리
  - 본사로 전달하는 월간 KPI 보고서에 "AI 인사이트 요약 섹션"을 번역 템플릿에 추가, 영어 독자가 맥락 없이도 이해할 수 있게 수치 단위·배경 주석 포함
  - 번역 후 도메인 용어 커버리지 자동 검증: Supabase glossary 테이블과 비교하여 미등록 신규 용어 리스트를 data-analyst에게 자동 플래그
- **적용 우선순위:** 🟡 중간 — 글로벌 AI 도구 도입 확대에 따라 신조어 유입 속도가 빨라지고 있음; 용어 통일 선행 시 후속 커뮤니케이션 오류 방지

### data-analyst
- **개선 제안:**
  - OEE 계산에 AI 예측 기반 "예상 가용률" 컬럼 추가 — 과거 다운타임 패턴과 현재 센서 상태를 결합한 간단한 회귀 모델 시범 적용 (Python + Supabase)
  - 비계획 다운타임 사건별 원인 분류 태깅 자동화: 장비 ID·정지 시간·재가동 시간 로그를 ML 클러스터링으로 유형 분류 후 주간 트렌드 시각화
  - 30일 단위 "유지보수 비용 vs. AI 개선 효과" 비교 슬라이드를 자동 생성, 본사 보고 자료로 직접 활용 가능한 포맷으로 산출
- **적용 우선순위:** 🔴 높음 — 현재 축적 중인 FMS 데이터가 예측 모델의 원재료; 지금 구조화하지 않으면 나중에 재처리 비용 발생

### web-builder
- **개선 제안:**
  - FMS 포털에 "장비 상태 타임라인" 페이지 추가 — Supabase Realtime으로 센서 이벤트를 스트리밍하고 이상 감지 시 빨간 배지로 즉시 표시
  - 현장 기술자가 스마트폰으로 정비 작업지시서를 1탭으로 수락/완료 처리할 수 있는 모바일 UI 구현 (PWA 형태, 오프라인 캐싱 포함)
  - 향후 디지털 트윈 연동을 고려하여 장비 계층 구조(Line → Machine → Component)를 API에서 페이지 라우팅까지 일관되게 반영하는 URL 구조 설계 및 적용
- **적용 우선순위:** 🟡 중간 — 타임라인 페이지는 기존 Supabase 인프라 재활용으로 1주 내 MVP 가능; 모바일 UI는 현장 수용성 검증 후 확대

### planner
- **개선 제안:**
  - 디지털 트윈 1단계 스펙 작성: 현재 FMS에서 수집 중인 데이터 항목을 기반으로 가상화 가능한 장비 범위 정의, 필요 추가 데이터 소스 및 DB 스키마 변경 목록 도출
  - "작업지시서 자동 생성 → 담당자 승인 → 실행 → 완료 기록" 4단계 승인 기반 워크플로우 화면 명세 작성 — evaluator 검증 기준도 명세에 포함
  - 장비별 예측 정비 이벤트 스케줄을 캘린더 뷰로 표시하는 기능 요구사항 정의, DB에 `predicted_maintenance_events` 테이블 스키마 설계
- **적용 우선순위:** 🔴 높음 — 디지털 트윈·예측 정비 두 방향 모두 planner의 사전 스펙 없이는 다른 팀이 착수 불가

### evaluator
- **개선 제안:**
  - 예측 정비 모델 검증 기준 문서화: "예측 → 실제 발생" 대조 정확도 목표치(예: ≥80%) 설정, 주간 리뷰 포함
  - 모바일 UI QA 시나리오에 오프라인 상태·저사양 기기·동시 다수 알림 케이스 추가 — 현장 실사용 환경 재현
  - 승인 기반 워크플로우 검증 시 "담당자 부재 시 에스컬레이션 경로 작동 여부" 항목을 3회 반복 체크리스트에 필수 포함
- **적용 우선순위:** 🟡 중간 — 신규 기능 출시 게이트 강화; 예측 모델 정확도 기준 수립은 data-analyst와 협의 후 즉시 착수 권장
