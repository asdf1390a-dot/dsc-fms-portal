# AI팀 일일 업그레이드 보고 — 2026-06-22

## 🔍 벤치마킹 인사이트

1. **Agentic AI가 예방 정비의 표준으로 부상**: 단순 이상 감지를 넘어 부품 재고 확인 → 기술자 배정 → 작업지시서 발행까지 자율적으로 처리하는 에이전트형 AI가 2026년 제조업 표준으로 자리 잡고 있음. 선도 제조사는 정기 정비 업무의 40~60%를 AI가 end-to-end 자동화 중.

2. **자동차 부품 제조 OEE 개선 실증 사례**: Oxmaint AI 예지보전 도입 후 14개월 만에 OEE 58% → 82% 향상, 비계획 다운타임 71% 감소, 생산 능력 $2.9M 회복. IoT 센서 기반 진동·열·음향 데이터 융합으로 고장 30~50% 조기 감지 달성.

3. **멀티 에이전트 협업 아키텍처가 핵심**: IBM·Rockwell·NVIDIA 모두 단일 AI가 아닌 전문화된 에이전트 간 협업(agent-to-agent coordination) 구조를 권장. 기존 레거시 OT 시스템과의 API 어댑터·미들웨어 연동이 도입 성공의 관건.

4. **엣지 AI + 5G 융합으로 실시간 대응력 강화**: 2026년 핵심 기술 트렌드로 엣지 AI와 5G 결합이 부상. 공장 센서 데이터를 클라우드 왕복 없이 현장에서 즉시 처리해 2~4주 전 장비 고장 예측, 교대 인계 자동화 실현.

5. **프로세스 기반 선행 작업이 AI 도입 ROI를 결정**: AI 도입 속도가 가장 빠른 제조사는 TPM(전사적 생산 보전) 등 구조화된 프로세스 규율이 이미 갖춰진 곳. 데이터 품질과 표준화가 AI 모델 정확도의 기초. 고영향 유스케이스(예지보전, 품질관리)부터 시작해 점진적 확대 권장.

## 🟢 팀원별 업그레이드 제안

### translator
- 개선 제안:
  - **용어 일관성 DB 구축**: 자동차 부품 제조 도메인(OEE, MTBF, TPM, 예지보전 등) 한↔영 표준 용어집을 Supabase 테이블로 관리하고, 번역 시 RAG 방식으로 참조하도록 워크플로우 개선
  - **컨텍스트 메모리 활용**: 본사-인도 커뮤니케이션에서 반복되는 프로젝트명·부서명·약어를 세션 컨텍스트로 유지해 번역 일관성 향상
  - **번역 품질 체크리스트**: 기술 문서 번역 후 evaluator 검토 전 자가 검증 항목(숫자 단위, 부품 코드, 날짜 형식) 표준화
- 적용 우선순위: 🔴 높음 — 용어 불일치는 본사 보고서 오해로 직결됨

### data-analyst
- 개선 제안:
  - **실시간 OEE 대시보드 쿼리 최적화**: Supabase에서 OEE·다운타임·생산량 KPI를 실시간 집계하는 뷰(View) 또는 Edge Function 구성으로 Excel 수동 집계 의존도 축소
  - **예지보전 데이터 파이프라인 설계**: IoT 센서 데이터(진동·온도)를 Supabase로 수집하는 파이프라인 설계 착수 — 향후 AI 예측 모델 연동 기반 마련
  - **트렌드 리포트 자동화**: 주간·월간 KPI 리포트를 CSV 수동 작업에서 Supabase + 스케줄러 기반 자동 생성으로 전환, planner와 스키마 사전 협의
- 적용 우선순위: 🔴 높음 — OEE 실시간 가시성은 경영 의사결정의 핵심

### web-builder
- 개선 제안:
  - **예지보전 알림 UI 모듈 추가**: Next.js 14 FMS 포털에 장비 상태 경보 컴포넌트(색상 코딩: 정상/주의/위험) 구현 — Supabase Realtime 구독으로 실시간 반영
  - **모바일 최적화 강화**: 현장 기술자가 스마트폰으로 작업지시 조회·완료 처리할 수 있도록 PWA(Progressive Web App) 전환 또는 모바일 반응형 레이아웃 개선
  - **작업지시서(Work Order) 자동 생성 흐름**: 알림 발생 → 작업지시 자동 Draft → 담당자 배정 UI 플로우를 planner와 협력해 구현
- 적용 우선순위: 🔴 높음 — 현장 접근성은 AI 도입 효과를 현장에 전달하는 마지막 접점

### planner
- 개선 제안:
  - **에이전트 오케스트레이션 설계 선행**: 멀티 에이전트 협업 구조(translator·data-analyst·web-builder·evaluator 연계 흐름)를 시각적 플로우차트로 문서화하고 각 에이전트 I/O 인터페이스 정의
  - **DB 스키마 — IoT 데이터 테이블 설계**: `equipment_sensors`, `maintenance_events`, `work_orders` 테이블 설계를 data-analyst와 협력해 선행 완료, 향후 AI 모델 연동 고려한 컬럼 구조 확정
  - **기능 명세서 버전 관리**: GitHub 이슈·마일스톤으로 기능 명세를 추적하고, 우선순위 변경 이력을 남겨 팀 전체 컨텍스트 공유
- 적용 우선순위: 🟡 중간 — 선행 설계 품질이 web-builder 개발 속도를 직접 결정

### evaluator
- 개선 제안:
  - **3단계 검증 체크리스트 표준화**: (1) 기능 동작 확인 → (2) 엣지 케이스·예외 처리 검증 → (3) 실제 데이터로 시나리오 테스트 의 3회 반복 구조를 문서화하고 각 단계 합격 기준 명시
  - **자동화 테스트 커버리지 확대**: Next.js 포털 핵심 API 라우트(장비 상태 조회, 작업지시 생성)에 대한 통합 테스트 추가 제안 — web-builder와 협업으로 테스트 케이스 작성
  - **회귀 검증 자동화**: 새 기능 배포 시 기존 KPI 대시보드·번역 결과물이 깨지지 않는지 자동 체크하는 smoke test 스크립트 도입
- 적용 우선순위: 🟡 중간 — 반복 검증 자동화로 evaluator 리소스를 고난도 시나리오에 집중 가능
