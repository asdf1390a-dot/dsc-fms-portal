# AI팀 일일 업그레이드 보고 — 2026-07-06

## 🔍 벤치마킹 인사이트

1. **자동차 부품 제조사 OEE 58% → 82% 달성 사례**: 실제 중소형 자동차 부품 제조사가 AI 예측 정비 도입 후 OEE가 24%p 상승하고, 비계획 다운타임이 71% 감소하며 $2.9M의 생산 능력을 회수. DSC Mannur와 규모·업종이 유사한 만큼 직접 벤치마크로 활용 가능. (출처: oxmaint.com)

2. **예측 정비 시장 급팽창, 그러나 도입 격차 존재**: 2026년 $171억 규모의 예측 정비 시장이 2034년 $974억으로 성장(CAGR 24.3%) 예상. 전체 정비팀의 2/3가 2026년 말 AI 도입 계획이지만, 실제 완전 구현은 1/3 미만. 지금 착수하는 공장이 경쟁 우위를 선점하는 시기.

3. **기술 선택 전 목표 지표 먼저 정의하라**: IBM·Augury 등 선도 기업이 공통 권고하는 Best Practice — OEE, 가동률(Uptime), 반응 정비 비율(Reactive Maintenance %) 목표값을 먼저 확정한 뒤 기술 스택을 역방향으로 선정. 기술 주도가 아닌 성과 주도(Outcome-first) 접근이 ROI 달성 기간을 단축.

4. **Edge AI + 5G로 실시간 설비 차단 자동화**: 2026년 핵심 기술 트렌드는 Edge AI와 5G 결합 — 설비 재배치·속도 조절·긴급 정지 의사결정을 클라우드 왕복 없이 현장에서 밀리초 단위로 실행. 진동·열화상·음향 센서 융합 AI가 고정 임계값 모니터링 대비 장애를 30~50% 더 일찍 감지.

5. **AI가 제조 착수 전 불량을 예측하는 시대**: 2026년 가장 주목받는 품질 혁신은 AI 기반 사전 결함 예측(Pre-manufacturing Defect Prediction). 생산이 시작되기 전에 공정 파라미터·재료 데이터·과거 불량 패턴을 분석해 불량 발생 가능성을 경보. 사후 검사 비용을 구조적으로 절감.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안**:
  - **자동차 부품 도메인 특화 AI 번역 파인튜닝**: 한국 본사 표준 용어(공정 코드, 부품 번호, 품질 규격 기호)를 학습시킨 커스텀 번역 프롬프트 구축. 범용 번역 모델의 오역률을 줄이고 기술 문서 신뢰도 향상.
  - **화상회의 실시간 자막 워크플로우 표준화**: 본사-인도 정기 회의 시 AI 실시간 한↔영 자막을 적용하고, 회의 후 요약본을 자동 생성하여 Supabase에 저장하는 파이프라인 설계.
  - **긴급 이슈 번역 SLA 정의**: 설비 다운·품질 클레임 등 긴급 상황 커뮤니케이션은 15분 내 번역 완료 기준 수립 및 escalation 경로 문서화.
- **적용 우선순위**: 높음 — 본사 에스컬레이션 지연이 생산 손실로 직결

### data-analyst
- **개선 제안**:
  - **OEE를 북극성 지표로 설정**: 가용성(Availability)·성능(Performance)·품질(Quality) 3요소를 Supabase에서 자동 계산하는 OEE 뷰(View) 구현. 현재 산발적 KPI 수집을 단일 지표 체계로 통합.
  - **불량률 선행 지표 발굴**: AI 예측 정비 사례에서 검증된 진동·온도 데이터와 불량률 간 상관분석 수행. 현재 후행 분석(Post-hoc) 중심에서 선행 경보(Leading Indicator) 체계로 전환 로드맵 수립.
  - **주간 자동 KPI 리포트 템플릿 완성**: data-analyst가 매주 반복 수작업하는 엑셀 정리를 Supabase 쿼리 + 자동 생성 PDF/Markdown 보고서로 대체, 분석 시간을 실질적 인사이트 도출에 집중.
- **적용 우선순위**: 높음 — OEE 기준선 없이는 AI 도입 효과를 측정할 수 없음

### web-builder
- **개선 제안**:
  - **OEE 실시간 대시보드 구현 우선순위 상향**: Supabase Realtime + Next.js 14 Server Components 조합으로 라인별·교대별 OEE를 초 단위 갱신. 현재 정적 보고서 기반에서 라이브 운영 화면으로 전환.
  - **PWA 오프라인 모드 추가**: 공장 내 Wi-Fi 불안정 구간을 고려해 Service Worker 기반 오프라인 캐시 구현. 현장 기술자가 네트워크 없이도 작업 지시서·설비 매뉴얼 조회 가능.
  - **AI 채팅 위젯 MVP 착수**: FMS 포털에 Claude API 연동 최소 기능 챗봇(설비 이력 조회·작업 지시 생성) 프로토타입 제작. 전체 AI 어시스턴트 구현 전 사용성 검증 선행.
- **적용 우선순위**: 중간 — OEE 대시보드 먼저, PWA/챗봇은 2단계 진행

### planner
- **개선 제안**:
  - **Outcome-first 기능 명세 프레임워크 도입**: 신규 기능 명세 작성 시 "어떤 OEE/다운타임 목표를 몇 % 개선하는가"를 첫 번째 필드로 고정. 기술 스펙보다 성과 지표를 앞세우는 IBM 권고 방법론 적용.
  - **예측 정비 데이터 레이어 스키마 설계 착수**: 센서 로그(sensor_readings), 장애 이벤트(failure_events), 정비 이력(maintenance_logs), 부품 재고(spare_parts) 4개 테이블 초안 작성. 향후 Edge AI 연동 기반 선행 구축.
  - **멀티 에이전트 에스컬레이션 플로우 다이어그램 작성**: 설비 이상 감지 → 정비 스케줄링 → 생산 계획 조정으로 이어지는 3단계 핸드오프 흐름을 시퀀스 다이어그램으로 시각화하여 팀 공유.
- **적용 우선순위**: 높음 — 스키마와 플로우 설계가 web-builder 구현의 선행 조건

### evaluator
- **개선 제안**:
  - **OEE 기준선 대비 AI 기능 효과 측정 프레임워크**: AI 어시스턴트·예측 알림 등 신규 기능 출시 전후 OEE 변화를 측정하는 A/B 비교 체크리스트 작성. "배포했다"가 아닌 "몇 % 개선됐다"를 QA 완료 기준으로 격상.
  - **Playwright E2E 테스트 커버리지 목표 설정**: FMS 포털 핵심 플로우(설비 등록→작업 지시 생성→완료 처리→KPI 반영) 4단계에 대한 자동화 테스트 100% 커버 목표 수립 및 CI 파이프라인 연동 일정 확정.
  - **AI 출력 허용 오류율(Error Budget) 정의**: 번역 오역, 분석 이상치, 챗봇 오답에 대한 허용 임계값을 수치로 정의. 검증 3회 반복 기준에 "AI 출력 품질 게이트" 항목 추가.
- **적용 우선순위**: 높음 — OEE 측정 없는 QA는 기능 검증에 그침, 사업 가치 검증으로 확장 필요

## 💡 오늘의 효율화 제안

1. **"Outcome-first" 주간 스프린트 도입**: 매주 월요일 planner가 해당 주 기능의 OEE·다운타임 기여 목표값을 팀에 공유하고, 금요일 evaluator가 실측치와 비교하는 2분짜리 루프를 정례화. 기술 완료(Done)와 성과 달성(Impact)의 간극을 주 단위로 좁히는 가장 빠른 팀 레벨업 방법.

2. **Supabase Edge Functions로 알림 파이프라인 통합**: data-analyst의 KPI 이상 탐지 → translator의 본사 알림 발송 → evaluator의 검증 완료 신호를 Supabase Edge Functions 하나의 트리거 체인으로 연결. 현재 Slack·이메일·수동 보고가 혼재하는 알림 분산을 단일 파이프라인으로 통합하면 대응 시간을 평균 40분에서 5분 이내로 단축 가능.
