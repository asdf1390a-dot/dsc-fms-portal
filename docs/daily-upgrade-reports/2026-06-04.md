# AI팀 일일 업그레이드 보고 — 2026-06-04

## 🔍 벤치마킹 인사이트

1. **백오피스 통합이 최고 ROI 영역** — 생산 스케줄링·구매·품질관리·고객 주문 관리 간 수동 인계(핸드오프)가 전체 지연의 대부분을 유발. 중소 제조사(25~500명)가 워크플로우 자동화 도입 후 12개월 내 납기 준수율 18~34% 향상 달성. 공장 바닥이 아닌 '부서 간 경계'가 핵심 자동화 대상.

2. **제조 AI 준비도 격차 심각** — 98%의 제조사가 AI 자동화를 검토·도입 중이나, 완전한 스케일 운용에 준비됐다고 답한 비율은 20%에 불과. 선도 기업과 나머지의 격차가 2026년 확대 중. 기술보다 거버넌스·데이터 품질·인력 역량이 준비도의 병목.

3. **자동차 부품 AI 예측정비 시장 급성장** — 자동차 예측정비 시장이 2030년까지 167억 5천만 달러 규모로 성장 전망. Azure AI·AWS·Google AI 플랫폼 기반 통합이 주류화되고, AI 비전 도구(UVeye, Bosch)는 5분 내 차량 360도 검사를 표준화. 47%의 글로벌 제조사가 이미 예측정비 기술 도입 완료.

4. **A2A 협력 + MCP가 2026년 산업 AI 표준 아키텍처** — 에이전트 간 협력(Agent-to-Agent)과 Model Context Protocol(MCP)이 라이브 데이터 소스와 AI 에이전트를 연결하는 공장 AI의 핵심 인프라로 자리잡음. 단일 에이전트가 아닌 역할별 전문 에이전트가 협력하는 멀티 에이전트 시스템이 복잡한 생산 제약(용량·인력·자재) 실시간 조율.

5. **엣지 컴퓨팅 + 저지연 네트워크가 AI 실시간 의사결정의 전제 조건** — 공장 장비에서 AI 모델을 직접 실행하는 엣지 추론이 네트워크 레이턴시 제거 및 오프라인 지속 운영을 보장. 고대역폭 연결·엣지 컴퓨팅·저지연 네트워크 인프라 구축이 모든 실시간 알림·의사결정 시스템의 필수 선행 조건으로 명시됨.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 자동차 부품 제조 산업 표준 온톨로지(IATF 16949, OEM 코드 체계)를 번역 컨텍스트에 통합해 기술 문서 정확도 향상
  - 본사↔인도 커뮤니케이션에서 반복 등장하는 승인 코멘트·품질 보고 패턴을 AI 프롬프트 템플릿으로 사전 정의, 번역 시간 50% 단축 목표
  - MCP를 활용해 Supabase 번역 메모리 DB와 AI 번역 도구를 직접 연결, 이전 번역 결과를 실시간 참조
- **적용 우선순위:** 🔴 High — 기술 용어 불일치는 품질 판정 오류로 이어질 수 있는 고위험 영역

### data-analyst
- **개선 제안:**
  - 백오피스 통합 관점에서 생산 스케줄·구매 발주·품질 불량 데이터의 3-way 조인 뷰 구축, 부서 간 지연 원인 자동 식별
  - Azure AI 또는 AWS AI 서비스를 Supabase와 연동해 KPI 이상치 탐지에 클라우드 ML 모델 활용 검토
  - 주간 납기 준수율(OTD) 트렌드를 자동 계산해 경영진 보고 슬라이드로 자동 생성하는 파이프라인 구축
- **적용 우선순위:** 🔴 High — 납기 준수율 자동 추적은 고객 신뢰도 유지의 직결 지표

### web-builder
- **개선 제안:**
  - FMS 포털에 MCP 연결 레이어 추가해 Supabase 실시간 데이터를 AI 에이전트가 직접 조회·수정할 수 있는 아키텍처 준비
  - 엣지 환경 고려: 공장 내 Wi-Fi 불안정 구간 대비 Next.js Service Worker + IndexedDB 기반 오프라인 캐싱 구현
  - 설비 상태 카드 UI에 "예측 잔여 수명(RUL)" 컬럼 추가 — 예측정비 데이터가 생기는 즉시 시각화 가능하도록 스키마·컴포넌트 사전 준비
- **적용 우선순위:** 🟡 Medium — MCP 아키텍처 준비는 향후 AI 에이전트 통합 비용을 크게 절감

### planner
- **개선 제안:**
  - 신규 기능 명세에 "AI 준비도 체크리스트" 섹션 추가: 해당 기능이 AI 에이전트 트리거·MCP 연결·감사 로그를 지원하는지 설계 단계에서 검증
  - A2A 멀티 에이전트 시나리오를 고려한 DB 스키마 설계: 에이전트 행동 로그(agent_id, action_type, payload, timestamp) 테이블 패턴 표준화
  - 부서 간 데이터 흐름 다이어그램(생산→품질→구매→출하)을 FMS 포털 기능 우선순위 결정의 기준 문서로 활용
- **적용 우선순위:** 🟡 Medium — 설계 단계의 AI 준비도 고려가 사후 리팩터링 비용 최소화

### evaluator
- **개선 제안:**
  - AI 생성 콘텐츠(번역 결과, 자동 보고서) 검증에 특화된 체크리스트 개발: 사실 정확성·도메인 용어 일치·컨텍스트 적합성 3축 평가
  - 예측정비 알림의 오탐(False Positive)·미탐(False Negative) 비율을 추적하는 검증 지표 도입
  - 3회 반복 검증 사이클에 "AI 보조 회귀 검사" 단계 추가: Playwright MCP로 UI 상태를 AI가 자동 스크린샷·비교
- **적용 우선순위:** 🟡 Medium — AI 출력물 품질 검증 체계 없이는 자동화 확대가 오히려 위험

## 💡 오늘의 효율화 제안

1. **AI 준비도 자가진단 실시** — "98%가 검토 중이나 20%만 준비됨"이라는 격차가 DSC Mannur에도 해당하는지 점검 필요. 팀원별로 (1) 데이터 품질, (2) 거버넌스·감사 로그, (3) 인력 AI 활용 역량 3개 항목을 5점 척도로 자가 평가하는 30분 워크숍 진행 제안. 결과를 `docs/ai-readiness/` 에 기록해 월별 추이 추적.

2. **백오피스 통합 로드맵 수립** — 현재 FMS 포털이 생산·설비 중심으로 구성되어 있으나, 구매 발주·품질 불량·납기 추적 간 자동 연계가 없는 상태. planner가 다음 스프린트에 "부서 간 데이터 흐름 매핑" 태스크를 추가하고, data-analyst와 협력해 수동 인계 지점 3개를 1개월 내 자동화하는 Quick Win 목표 설정 권고.
