# AI팀 일일 업그레이드 보고 — 2026-07-25

## 🔍 벤치마킹 인사이트

1. **Agentic AI의 부상**: 단순 이상 감지를 넘어 ERP 부품 재고 조회 → 기술자 배정 → 작업지시서 자동 생성까지 자율 실행하는 Agentic AI가 2026년 제조업 표준으로 자리잡고 있음. AI 예측 정비 도입 공장은 OEE(전체 장비 효율)가 15~20% 향상됨.

2. **자동차 부품 분야 예측 정비 ROI 명확화**: 선도 자동차 부품사들은 비계획 가동 중단 45% 감소, 정비 비용 28% 절감, 라인 가용성 99.7% 달성을 보고. 예측 정비 시장 규모는 2030년까지 $167.5억 달성 전망. 조기 경보 기능은 4~8주 내 MTTR 개선 효과가 측정 가능.

3. **AI 에이전트 간 협업 구조 필수화**: 장애 감지 에이전트 → 정비 스케줄링 에이전트 → 생산 운영 에이전트로 이어지는 핸드오프 구조가 핵심. 공유 컨텍스트·명확한 소유권·에스컬레이션 로직 없이는 70%의 프로젝트가 알람 피로로 실패함.

4. **AI 워크플로우 자동화 적용 범위 확대**: 품질 관리(컴퓨터 비전 기반 비적합 보고 자동화), 재고/공급망(AI 에이전트 자동 발주), 생산 스케줄링(제약 조건 인식 자율 최적화) 등 전 영역으로 확산. 스마트 제조 시장 규모 2025년 기준 $3,940억, 연 15% 성장 중.

5. **도입 실패 방지 전략**: 첫 적용 사례는 측정 가능하고 데이터가 충분하며 특정 팀이 소유한 범위로 제한해야 성공률 높음. 작업지시서 생성·품질 케이스 트리아지·생산 예외 조사가 자율 장비 제어보다 현실적인 출발점. 전면 프로그램 ROI는 단계적 구현 시 3~6개월 내 실현 가능.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 한↔영 번역 시 자동차 부품 제조 도메인 용어집(글로시) 구축 및 Supabase에 저장하여 일관성 확보
  - 본사(한국) 보고서의 KPI 수치(OEE, MTTR, MTBF 등) 번역 시 단위·맥락 보존 체크리스트 도입
  - 생산 현황 실시간 알림 번역 자동화 파이프라인 구축 검토 (웹훅 → 번역 → Slack/이메일)
- **적용 우선순위:** 🟡 중 — 도메인 용어집 구축부터 착수 (1주 내 초안 가능)

### data-analyst
- **개선 제안:**
  - Supabase 대시보드에 OEE·MTTR·비계획 가동중단 시간 추적 KPI 뷰 추가 (예측 정비 ROI 측정 기반 마련)
  - Excel/CSV 데이터 업로드 시 이상값 자동 감지 로직 강화 — Z-score 또는 IQR 기반 플래그 처리
  - 주간 트렌드 리포트를 자동 생성하여 `docs/weekly-kpi-reports/` 경로에 저장하는 파이프라인 구성
- **적용 우선순위:** 🔴 높음 — OEE 추적 뷰는 예측 정비 효과 증명에 즉시 필요

### web-builder
- **개선 제안:**
  - FMS 포털 장비 상태 페이지에 실시간 이상 알림 배지(badge) UI 컴포넌트 추가 (Next.js 14 Server Actions + Supabase Realtime 활용)
  - 작업지시서(Work Order) 모듈에 AI 생성 초안 기능 추가 — 장비 ID + 오류 코드 입력 시 정비 절차 자동 제안
  - 모바일 반응형 최적화 — 현장 기술자가 태블릿/스마트폰으로 작업지시서 확인·서명할 수 있도록 개선
- **적용 우선순위:** 🔴 높음 — 실시간 알림 컴포넌트가 현장 대응 속도 직결

### planner
- **개선 제안:**
  - 에이전트 간 핸드오프 흐름도 설계: 장애 감지 → 정비 스케줄 → 생산 조정 3단계 에이전트 아키텍처 명세 작성
  - DB 스키마에 `maintenance_events` 테이블 추가 — 장비 ID, 오류 유형, 감지 시각, 조치 완료 시각, 담당자 컬럼 포함
  - 신규 기능 명세 시 "측정 가능한 성공 지표" 항목 필수 포함 (예: 알림 응답 시간 목표 < 5분)
- **적용 우선순위:** 🟡 중 — 에이전트 아키텍처 명세 완료 후 web-builder와 동기화 필요

### evaluator
- **개선 제안:**
  - 예측 정비 알림 정확도 검증 체크리스트 표준화 — 오탐(False Positive) 비율 추적 및 임계값(< 10%) 설정
  - 최소 3회 반복 검증 외에 "운영 환경 모의 테스트" 단계 추가 — 실제 장비 데이터 샘플로 시뮬레이션
  - 검증 결과를 Supabase `qa_logs` 테이블에 자동 기록하여 QA 이력 추적 가능하도록 구성
- **적용 우선순위:** 🟡 중 — 오탐 비율 추적은 AI 알림 신뢰도 확보의 핵심 지표

## 💡 오늘의 효율화 제안

1. **팀 간 공유 컨텍스트 저장소 구축**: planner가 설계한 에이전트 아키텍처 명세, translator의 도메인 용어집, data-analyst의 KPI 정의를 단일 Supabase 테이블(`team_knowledge_base`)에 통합 저장. web-builder와 evaluator가 공통 참조점을 가지면 중복 해석 오류를 방지하고 핸드오프 마찰을 최소화할 수 있음.

2. **주간 AI 성과 리뷰 루틴 도입**: 매주 금요일 data-analyst가 OEE·MTTR 변화분을 자동 집계하고, evaluator가 QA 로그 기반으로 알림 정확도를 검토하는 30분 리뷰 루틴 설정. 이 데이터를 translator가 본사 보고용으로 번역하는 파이프라인을 연결하면 보고 준비 시간을 70% 이상 단축 가능.
