# AI팀 일일 업그레이드 보고 — 2026-06-10

## 🔍 벤치마킹 인사이트

1. **Agentic AI로의 전환** — 2026년 제조업 AI는 단순 경보 시스템에서 다단계 작업을 자율 실행하는 "에이전틱 AI"로 진화. Deloitte는 2026년 제조업 agentic AI 도입률이 6% → 24%로 4배 급증 예측. FMS 포털도 단순 데이터 표시를 넘어 자동 작업지시서 생성 방향으로 발전 검토 필요.

2. **예측정비 자동화 40~60%** — 선도 제조사들은 2026년까지 정기 유지보수 태스크의 40~60%를 AI로 자동화 (스케줄링·예비부품 관리·기술자 배정). 자동차 부품 분야 실증 사례: 예측정비 도입 후 비계획 다운타임 38% 감소, 정비 노동 생산성 18% 향상, 예비부품 재고 22% 감소.

3. **생성AI가 기술자 'Super-Mentor' 역할** — 2026년 생성형 AI는 500페이지짜리 OEM 매뉴얼을 수 초 내 파악해 현장 기술자에게 실시간 지침 제공. 컴퓨터 비전이 생산라인 24시간 감시하며 마이크로-스톱 포착. DSC Mannur 환경에서도 설비 매뉴얼 임베딩 및 AI 검색 적용 검토 가능.

4. **백오피스 워크플로우 자동화 ROI 최고** — 중소 제조사 평균 연 $34만 손실이 예방 가능한 워크플로우 비효율에서 발생. 생산 스케줄링-구매-품질관리-주문관리 간 연동 자동화가 공장 현장 자동화보다 ROI 높음. FMS 포털의 KPI 리포팅과 Supabase 백엔드 연동 강화가 핵심 기회.

5. **데이터 거버넌스가 AI 파일럿 성패 결정** — "AI 파일럿은 에이전트가 원시 센서 데이터를 쿼리할 때 실패한다"(Dataiku). 인증된 데이터 제품(governed data products) 기반 구조가 필수. DSC FMS 포털에서 Supabase 스키마 품질과 데이터 정합성 점검이 선행 조건.

## 🟢 팀원별 업그레이드 제안

### translator
- **개선 제안:**
  - 한↔영 번역 시 제조업 도메인 전문 용어집(DSC Mannur 자체 글로서리) 구축 및 AI 프롬프트에 컨텍스트로 주입. 본사(한국) ↔ 인도 현장 간 기술 문서 번역 품질 일관성 확보.
  - 번역 결과물을 FMS 포털 내 다국어 지원 모듈과 연결해 번역된 설비 상태 알림·작업지시서가 자동으로 현장 언어로 출력되도록 파이프라인 설계.
  - 오번역 위험이 높은 품질 기준값·규격 수치 등 숫자/단위 포함 문장은 이중 검증(evaluator 연계) 절차 도입.
- **적용 우선순위:** 🔴 즉시 — 도메인 용어집 초안 작성 (2주 이내 MVP)

### data-analyst
- **개선 제안:**
  - Excel/CSV 수기 작업에서 Supabase 실시간 뷰(View) + 자동 KPI 집계 쿼리로 전환. 주간 트렌드 리포트 자동 생성 스크립트 작성으로 반복 분석 시간 절감.
  - 2026 트렌드인 디지털 트윈 개념 적용: 설비별 가동률·고장률 시계열 데이터를 누적해 "가상 기준선" 수립, 편차 감지 알림 로직 추가.
  - 예측정비 ROI 측정 대시보드 신설 — 다운타임 비용, 예비부품 소모, 정비 공수를 통합한 단일 KPI 뷰 제공.
- **적용 우선순위:** 🟡 단기 — Supabase 자동 집계 뷰 구현 (1개월 이내)

### web-builder
- **개선 제안:**
  - Next.js 14 App Router 기반 FMS 포털에 실시간 알림 채널(Supabase Realtime) 연동 강화. 설비 이상 감지 시 브라우저 푸시 알림 → 작업지시서 자동 생성 UI 플로우 구현.
  - 2026 표준인 Edge Computing 친화적 아키텍처 준비: 서버 컴포넌트에서 무거운 데이터 집계를 처리하고 클라이언트 번들 최소화. Core Web Vitals LCP < 2.5s 목표 설정.
  - AI 채팅 위젯(설비 FAQ·정비 이력 검색) 포털 내 임베드 검토 — OpenAI/Claude API + Supabase pgvector 활용한 RAG 파이프라인 프로토타입.
- **적용 우선순위:** 🟡 단기 — Realtime 알림 연동 (2주), AI 채팅 위젯 (1분기 내)

### planner
- **개선 제안:**
  - UI/UX 설계 시 "에이전틱 워크플로우" 관점 도입: 사용자가 결과를 보는 화면뿐 아니라 AI가 자율 실행하는 백그라운드 플로우(자동 스케줄링·부품 발주 트리거)의 상태를 투명하게 보여주는 Human-oversight 대시보드 설계.
  - DB 스키마 설계 시 데이터 거버넌스 레이어 명시화: 원시 센서 데이터 테이블과 집계·검증된 KPI 테이블을 분리해 AI 쿼리 대상 명확화.
  - 기능 명세에 "AI 개입 지점" 항목 추가 — 어떤 의사결정을 AI가, 어떤 것을 사람이 최종 승인하는지 명시적으로 구분하는 RACI 매트릭스 작성.
- **적용 우선순위:** 🟡 단기 — 다음 기능 명세부터 AI 개입 지점 항목 필수 포함

### evaluator
- **개선 제안:**
  - QA 검증 체크리스트에 AI 출력물 검증 항목 추가: 번역 정확도, 데이터 집계 수치 크로스체크, 대시보드 KPI 값의 원천 데이터 대비 오차율 기준(±2% 이내) 설정.
  - 최소 3회 반복 검증 원칙에 "회귀 테스트" 관점 추가 — 신규 기능 배포 후 기존 핵심 KPI 페이지 자동 스크린샷 비교(Playwright 활용) 도입 검토.
  - 인도 현지 네트워크 환경(레이턴시 변동)을 고려한 성능 테스트 시나리오 정기 실행 — 느린 3G/4G 조건에서 FMS 포털 주요 페이지 로드 시간 측정 및 기준치 관리.
- **적용 우선순위:** 🟡 단기 — QA 체크리스트 개정 (1주 이내), Playwright 도입 (1개월 이내)

## 💡 오늘의 효율화 제안

1. **팀 내 "데이터 제품화" 스프린트 신설** — planner가 스키마를 설계하면 data-analyst가 즉시 집계 뷰를 작성하고 evaluator가 수치를 검증하는 2주 단위 데이터 제품화 사이클 도입. 현재 분산된 Excel 파일들을 Supabase 단일 진실 공급원(Single Source of Truth)으로 마이그레이션하는 목표를 설정하면 전체 팀의 AI 활용도가 함께 올라감.

2. **translator ↔ evaluator 공동 용어 검증 세션 (주 1회, 30분)** — 기술 번역 오류는 현장 의사결정 오류로 직결됨. 매주 번역된 설비 알림·보고서를 evaluator가 수치/단위 중심으로 교차 검증하는 짧은 세션을 정례화하면 재작업 비용을 사전에 차단할 수 있음.
